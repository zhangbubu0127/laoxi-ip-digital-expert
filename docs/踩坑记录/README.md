## 一、LLM 调用与输出

### 1. 推理吃满 max_tokens → 空输出退化模板
- **触发**：老板正常对话，小席突然回模板话
- **根因**：DeepSeek/MiMo 推理型模型先出 reasoning_content 再出正文，max_tokens 太小（200~800）被思考吃满，content 为空 → llm.py 遇 length 直接抛 → 降级模板
- **修复**：llm.py 空内容逐步加大 max_tokens 重试 3 次（×2 封顶 16000）；`_default_chat_generate` max_tokens 200→800→10000；system 加「直接给最终答复，不要输出思考过程」
- **来源**：讨论 08-03 #5#6、变更 08-03 #2#3

### 2. 调研生成被截断，误报「连不上模型」
- **触发**：老板问调研，回「暂时连不上模型」
- **根因**：deepseek-v4-flash 是推理模型，max_tokens=1000 太紧，thinking 吃满 → finish=length；同句测试群空内容走了重试成功，生产群有部分内容被截断 → llm.py 对有内容+length 直接 raise 不重试
- **修复**：finish=length 无论正文是否为空一律加大预算重试最多 2 次；research.py max_tokens 1000→3000；兜底文案从「连不上模型」改为「没成」
- **来源**：badcase 08-08 调研连不上模型

### 3. 席小文超时未回复
- **触发**：派单后席小文长时间无响应
- **根因**：DeepSeek 空输出螺旋，单线程阻塞
- **修复**：llm.py 空输出重试改为带「直接输出正文、不再推理」提示 + 2 次限时 + 预算步进 4000
- **来源**：变更 08-04 #8

### 4. 席小题不出选题（API 连不上）
- **触发**：生产群调研无响应
- **根因**：DeepSeek API 间歇性 ECONNREFUSED，进程跑 17h 连不上
- **修复**：杀旧进程重启；专家异常吞掉只记日志不回群
- **来源**：变更 08-08 #35

### 5. 主控回复退回模板（偶发）
- **触发**：正常对话突然回模板
- **根因**：推理型模型偶发 reasoning_tokens 占满 max_tokens，content 为空 + finish=length → llm.py 抛错 → 降级
- **修复**：同 #1
- **来源**：讨论 08-03 #5

### 6. 席小文脚本输出被截断（DeepSeek）
- **触发**：脚本只出半截
- **根因**：DeepSeek 偶发 reasoning 吃满 max_tokens，content 为空
- **修复**：llm.py 空内容逐步加大 max_tokens 重试 3 次（×2 封顶 16000），仍空才抛
- **来源**：变更 08-03 #2

### 7. 推理吃满预算 —— 对话预算用多少
- **触发**：老板问为什么推理吃满预算
- **根因**：max_tokens 是推理+正文总上限，预算太小被思考吃满
- **修复**：调研 GitHub 实践后，_default_chat_generate max_tokens 800→10000
- **来源**：讨论 08-03 #6

## 二、意图识别与路由

### 8. 「看一下表格」误判成确认已发布
- **触发**：老板发「看一下表格」→ 系统执行标已发 → 回「未找到」
- **根因**：意图识别 100% 押 LLM 单点，23 秒前刚确认完已发布，上下文污染；无关键词硬锚、无后果分级
- **修复**：Fix A 看排期表硬锚（`_VIEW_SCHEDULE_RE` 含排除词，planner 前拦截）；Fix B 确认已发布防呆（`_has_publish_confirm` 校验原文含确认词，无则不执行）；Fix C prompt 加固
- **来源**：badcase 08-08 看表格被误判

### 9. 「说安排」变真派单 —— 老板说「根据这个出内容吧」没派单
- **触发**：老板说「根据这个出内容吧」→ 被识别成「其他」→ 只聊天不派单
- **根因**：意图列表缺识别
- **修复**：intent.py 写脚本识别增强，controller.py 新增 `_force_script_task()` 强制走写脚本派单
- **来源**：变更 08-04 #6

### 10. 「审核一下」只聊天不派单
- **触发**：老板说「审核一下」→ 聊天不派单
- **根因**：意图列表里没有「审核」意图
- **修复**：intent.py 新增「审核脚本」意图，controller 新增 `_review_script` 派席小核
- **来源**：变更 08-04 #10

### 11. 「怎么没@我提醒」被误判为确认排期
- **触发**：老板问「怎么没@我提醒」→ 被当成确认排期
- **根因**：planner prompt 语义模糊
- **修复**：planner prompt 语义澄清 ——「怎么没提醒」是提醒的疑问、不是确认排期
- **来源**：变更 08-07 #31

### 12. 智能体「不够智能」—— 问「刚才的选题你还能看见么」回空话
- **触发**：老板问「刚才的选题你还能看见么」→ 回得暖心但只是空话
- **根因**：(1) 识别层：「能看见」不在查选题关键词表，被归闲聊；(2) 行为层：闲聊分支依赖死板【提议】标记，LLM 把提议说成自然口语就不带标记 → 登记不了 → 空话
- **修复**：意图层新增「查记录」+ `_LOOKUP_HINTS` 兜底；行为层新增【行动】JSON 契约，立即动作当场执行；契约升级线：「闲聊不承诺」→「提议必须带标记」→「承诺即兑现」
- **来源**：讨论 08-05 #1

### 13. 选题 N 依据回全部
- **触发**：「选题四的依据」→ 回全部 5 条依据
- **根因**：`_ask` speaker==席小题且有 basis 时直接 load_basis 全部 dump，不解析序数
- **修复**：新建 `basis.py` 公共序号解析，`match_index` 命中时只回那一条
- **来源**：badcase 08-11、讨论 08-11 #1

### 14. 拍板消息「实质修改+放行词」时放行词抢先
- **触发**：「早三年吧，然后就可以了」→ 只认「可以了」当放行定稿，「早三年」改稿指令被丢
- **根因**：`_is_pass` 整条子串匹配 `_PASS_HINTS`，关键词门先于 planner LLM，不区分「否定式放行」与「实质改稿指令」
- **修复**：`_resolve_doubt` 在 `_is_pass` 前加 `_has_concrete_modification` 判定 —— 含数字量词或改稿动词 → 走改稿路径；「不用改/别改」否定式仍归放行
- **来源**：badcase 08-10、讨论 08-10 #2

### 15. 排期负责人不丢
- **触发**：「排8/6 14:00 负责人老席」→ 负责人丢失
- **根因**：`_extract_date` 不认「8月6日」中文格式
- **修复**：增加中文日期支持 `(\d{1,2})月(\d{1,2})日`
- **来源**：变更 08-06 #21

## 三、流水线编排与派单

### 16. 排期生成 3 条垃圾占位行
- **触发**：「排8/8 18:15 负责人张艺宝」→ 生成 3 条垃圾行（曝光选题1/2/3，负责人写死席小文）
- **根因**：流水线超时 180s 被清 → `_schedule_entries` count 默认 3、owner 写死、type 默认曝光、topic 编造
- **修复**：新增 `_parse_owner` / `_explicit_count`；无明确数量返回空；owner 不再写死；无条目时明说「没指定排哪条选题」绝不编占位
- **来源**：badcase 08-08 排期生成垃圾行

### 17. 老板确定选题/类型不能及时同步排期表
- **触发**：老板定稿后立即排期，系统不认
- **根因**：无定稿上下文记忆
- **修复**：新增 `_draft_ctx` / `_last_passed` 记录刚定稿选题+类型，`_try_pick_topic` 增 `_PASSED_HINTS` 匹配确认语
- **来源**：变更 08-05 #13

### 18. 脚本含「----」导致整行被跳过（多维表格漏同步）
- **触发**：脚本内容含 `----` → 排期表漏行
- **根因**：`load_schedule` 跳过逻辑看整行是否含 `---`
- **修复**：跳过逻辑只匹配第一格
- **来源**：变更 08-06 #22

### 19. 发布提醒不@负责人
- **触发**：发布前提醒没有 @负责人
- **根因**：系统无「负责人名→open_id」映射
- **修复**：`config/roles.json` 加 `owner_ids`，`identity.py` 加 `resolve_owner_open_id(name)`
- **来源**：变更 08-06 #23

### 20. 发布提醒重复提醒
- **触发**：每条消息都被反复提醒
- **根因**：进程重启内存清空 → 60 分钟窗口内每条都被反复提醒
- **修复**：`_REMINDED` 落盘持久化（`workspace/已提醒发布.json`）
- **来源**：变更 08-06 #24

### 21. 发布前 1 小时提醒从不触发
- **触发**：发布提醒从不出现
- **根因**：节流 bug —— 每轮无脑刷新 last_remind
- **修复**：`_maybe_send_publish_reminders` 改为返回 bool，只在 True 时才重置 last_remind
- **来源**：变更 08-07 #30

### 22. 席小文出稿带「【席小文】」前缀
- **触发**：老板看到机器标记
- **根因**：出稿模板带【席小文】前缀
- **修复**：出稿模板去掉前缀，主控识别改成按「## 脚本」行头匹配
- **来源**：变更 08-06 #25

### 23. 审核体验四联修
- **触发**：写脚本断链/审核刷屏/审核结论冗长/审核误判
- **根因**：派单任务带全文刷屏；审核结论没分层；三态判定缺失
- **修复**：写脚本连续性：`_resolve_script_task()` 解析「第N个」；审核不刷屏：原文走 context_store；席小核改双段输出（公开段+详情段存档）；三态判定只认明确拒稿信号
- **来源**：变更 08-04 #7

### 24. 审核疑问点→暂停后无闭环
- **触发**：席小核提疑问后不@老板，老板答复后不学习/不修改/不复审
- **根因**：doubt 分支无闭环设计
- **修复**：doubt 分支改挂 `wait_boss` 状态 + @老板展示疑问点；老板答复后落已确认规则 → 派席小文修改 → 复审闭环
- **来源**：变更 08-04 #12

## 四、排期表与数据同步

### 25. 标已发不容忍日期笔误
- **触发**：「8/3 ... 已发布」→ 排期表里是 8/8 → 回「未找到」
- **根因**：`_resolve_publish_row` 日期不符直接跳过，不进标题模糊匹配
- **修复**：返回 `(row, date_mismatch)` —— 日期对得上优先；日期对不上但标题唯一命中时容忍笔误，回执注明
- **来源**：badcase 08-08 标已发日期笔误

### 26. 标已发无日期无标题找不到
- **触发**：「已核对好，可以确定是已发了」→ 回「没找到」
- **根因**：`_try_mark_published` 只在消息显式带「日期+标题」时才能定位，无回落机制
- **修复**：新增 `_last_passed[chat_id]` 回落 —— 无日期+标题时用最近定稿选题模糊匹配；唯一命中才标已发
- **来源**：badcase 08-10、讨论 08-10 #1

### 27. 查选题答非所问（dump 整版）
- **触发**：「我选择出脚本的选题你还能看到么」→ dump 整版 5 个选题
- **根因**：`_lookup_topic_record` 不认「刚定稿」上下文，直接 load_basis 整版 dump
- **修复**：新增 `_asks_chosen` 判定，优先回 `_last_passed` / `_draft_ctx`
- **来源**：badcase 08-08 查选题答非所问

### 28. 确认已发布/数据回流不支持自然语言
- **触发**：自然语言说「已发布了」→ 不识别
- **根因**：只认 `M/D 日期 + 选题` 字面格式
- **修复**：优先用 params.date/topic；正则兜底增强 —— 剥标点后按标题模糊匹配
- **来源**：变更 08-08 #32

### 29. 跨消息暂存待回流数据
- **触发**：数据与已发布确认分两条消息 → 无法连动
- **根因**：无跨消息暂存机制
- **修复**：模块态 `_pending_reflow`（7200s TTL），标完已发后自动补回流
- **来源**：变更 08-08 #33

### 30. params 路径精确匹配失败即放弃
- **触发**：planner LLM 把「8/7 19:45」整个塞进 params.date → 匹配不到
- **根因**：精确匹配无容错
- **修复**：`_resolve_publish_row` date 剥出 M/D（去掉时间）后模糊匹配
- **来源**：变更 08-08 #34

### 31. 选题依据追问「对不上」
- **触发**：追问选题四依据 → 回的不是选题四的理由
- **根因**：(1) LLM 序号漂移；(2) 存盘只存依据不存题目
- **修复**：席小题 prompt 强制【依据】段第 N 条=上方第 N 条选题；context_store 改存 (topics, basis) 配对
- **来源**：讨论 08-03 #1

### 32. 出选题依据段 1 选题写了 3 条理由
- **触发**：每个选题对应多条理由（按取材来源拆）
- **根因**：LLM 按来源拆多条
- **修复**：prompt 强化「每个选题只写一条理由，把多个取材来源的支撑合并进同一条」
- **来源**：变更 08-06 #20

### 33. 老板放行后不立即问排期
- **触发**：老板放行后系统不主动问排期
- **根因**：只有「席小核审核通过」出口会问排期
- **修复**：抽 `_ask_schedule()` 统一两个定稿出口
- **来源**：变更 08-06 #19

## 六、提示词与输出格式

### 41. 席小文脚本固定输出格式
- **触发**：老板要求六段式：标题/口播正文/结构拆解/封面文字/钩子词/投放建议
- **根因**：（功能需求）
- **修复**：xiaowen.py 六段式固定模板，修改时版本号递增 v1→v2
- **来源**：讨论 08-03 #3

### 42. 审核意见要直接 @席小文去改正
- **触发**：审核后不会自动改正
- **根因**：审核后缺少自动改正闭环
- **修复**：席小核判定含「需改/红线/黄线/❌」→ 主控直接 @席小文「修改这条脚本：审核意见」→ wait_he → wait_fix → 复审闭环，最多 2 轮
- **来源**：讨论 08-03 #4

### 43. 专家 prompt 过度约束
- **触发**：专家失去模型原本能力
- **根因**：prompt 限制太多
- **修复**：专家 prompt 去约束化（保留承重锚点，改引导性表述）
- **来源**：变更 08-07 #28

### 44. 规则类型化
- **触发**：审核看法不能被记住并下次自动对齐
- **根因**：rules 无分类
- **修复**：rules.py 加 `type` 字段（表达偏好/事实规则/内容策略/禁止事项），按类型分组注入
- **来源**：变更 08-07 #29

### 45. 知识库语料分离
- **触发**：老板要求「说话逻辑、说话风格分开几个库」
- **根因**：语料混在一起
- **修复**：新建风格库目录+加载器，席小文按风格写作，学习规则按用户分库
- **来源**：变更 08-05 #18

### 46. 主控走关键词/19 类意图表不够智能
- **触发**：意图识别经常不准
- **根因**：纯规则，缺 LLM 语义理解
- **修复**：新增 `planner.py` 规划器，一次 LLM 调用产出（自然回复, 可选动作）
- **来源**：变更 08-07 #27

## 七、运维与工程

### 47. 小席连回两条消息
- **触发**：小席连着回复两条
- **根因**：重启时 pgrep 模式匹配不到实际命令行，旧进程没被杀掉，两套小席同时消费
- **修复**：按 pid 杀掉旧进程；pgrep 模式要匹配 `skin.multi_main`
- **来源**：讨论 08-03 #7

### 48. 熔断账本重启清零
- **触发**：重启后 token 花费从 0 开始
- **根因**：`circuit.py` 只写盘不读盘，init 硬编码 `spent=0`
- **修复**：`__init__` 新增 `_load()` 读 `memory/token账本.md` 恢复 spent；无文件 → 0
- **来源**：iteration 08-02 P1 补齐

### 49. 机器人已读表情（奋斗）
- **触发**：老板要求加已读表情
- **根因**：lark-cli emoji_type 合法值不确定，官方文档域名屏蔽抓取
- **修复**：逐个实测候选 emoji —— FIST/FIGHT/FIRE/GO/DETERMINED/FIGHTING 无效，MUSCLE/SALUTE/STRIVE 有效，选 STRIVE
- **来源**：讨论 08-03 #2

### 50. 真多 bot 模式专家不自触发
- **触发**：专家 bot 在群里不响应
- **根因**：飞书 open_id 按应用隔离，bots.json 是小席视角，跨应用比对永不命中
- **修复**：专家自触发改按 mention 名 + sender_type=bot 判定
- **来源**：变更 08-03 #1

### 51. 写脚本流水线超时 + 重复派单
- **触发**：脚本写到一半超时，又重新派单
- **根因**：`_PIPE_TIMEOUT` 太短；`_force_script_task` 已有活跃管线时不跳过
- **修复**：`_PIPE_TIMEOUT` 180s→300s；已有活跃管线时跳过
- **来源**：变更 08-24 #44

### 52. 说两条脚本只出一条
- **触发**：「给我出两条脚本」→ 只出一条
- **根因**：意图层提取的 count 没传给席小文
- **修复**：`_write_script` 加 params 形参，`_apply_script_count` 把条数写进派单任务
- **来源**：变更 08-05 #16

## 高频问题模式总结

| 模式 | 涉及条目 | 根因共性 | 通用解法 |
|---|---|---|---|
| **推理型模型吃预算** | 1-6 | max_tokens 被 reasoning 占满 | 预算给足（8000+）+ 空输出重试 + system 禁思考 |
| **意图单点押 LLM** | 8-12 | 无关键词硬锚、无后果分级 | 关键词门拦截 + LLM 识别 + 高后果防呆 |
| **上下文不回落** | 25-27、34-37 | 执行器缺最近上下文锚点 | 统一 `_last_passed` 回落机制 |
| **流水线断链** | 16-24 | 超时/无闭环/无持久化 | 超时恢复 + 闭环设计 + 状态落盘 |
| **关键词匹配粗糙** | 14、30 | 整条子串匹配不区分语义 | 放行词前加实质修改判定；日期模糊匹配 |
