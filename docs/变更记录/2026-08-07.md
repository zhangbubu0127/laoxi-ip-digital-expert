## 18:25 · planner.py + test_planner.py · 修复「怎么没@我提醒」被规划器误判为「确认排期」

**连带发现**（上条日志还原）：18:18:37 老板「怎么没@我提醒」→ 规划器判定 `action=确认排期` → 执行停止提醒 → 回「没有需要确认的发布提醒。」（与 18:23 的节流 bug 是两回事，这条是误路由）。

**根因**（代码核实）：`_PLANNER_SYSTEM` 22 个动作只列名字、不给语义，「确认已发布/确认排期」靠模型从名字猜；老板话里带「提醒/排期」，模型把抱怨联想成「确认排期」（其执行器正是停止发布提醒）→ 一句追问被当确认动作执行。

**改动**：`planner.py` 判断段补 3 行语义澄清——「已发布/这条发了」→确认已发布（排期表标已发）；「排期没问题/可以发了」→确认排期（停止该条发布提醒）；「怎么没提醒/没@我/提醒呢」是提醒的疑问、**不是确认排期**，不写动作、自然回复（必要时自查排期表）。

**测试**：`test_planner` 新增 1 例锁 prompt 语义（确认已发布/确认排期有明确语义 + 「怎么没提醒」「不是确认排期」边界句）。14 例全绿 + controller 154 绿。
