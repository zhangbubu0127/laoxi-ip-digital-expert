# 直播稿清洗 实施计划

> 执行方式：本会话内联执行（逐字稿全文上下文已加载在此会话，派子代理会丢失上下文，不利于内容提取）

**Goal:** 清洗 2 份直播稿，搭建「直播稿清洗工作流」独立环节，沉淀 4 类知识（语言风格/内容口径/直播语料/家长问题带应答）。

**Architecture:** 复用土豆「结构化数据清洗工具」的工作流原则（原始素材→去重/结构化→标签沉淀→可检索复用），按直播稿特点定制 4 类 schema。清洗工作流为知识库链路的「前一步」，产出落 knowledge/ 事实层。

**Tech Stack:** Markdown 知识文件；git + docs/archive/ 备份规则。

## Global Constraints

- 改现有文件前，旧版先拷贝到 `docs/archive/`，命名 `原名-YYYYMMDD-HHMM.md`
- 内容事实与现有 `业务事实/`（项目详情/费用数据/院校信息/就业数据）核对去重，差异才记
- 家长问题必须带席老师应答
- 人名称谓：老席=席校长=习校长=习未辛（同一人）；清北语交=清华/北大/北语/北交
- 不提交 git（仓库有未完成的 P0 开发工作，改动保持本地）
- 不装新依赖、不改 .env/密钥
