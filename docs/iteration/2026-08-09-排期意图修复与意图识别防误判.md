# 迭代记录：排期意图修复（占位乱象） + 标已发日期容错 + 意图识别防误判

日期：2026-08-09
关联：**两个连续生产事故**——① 8/8 17:10「排8/8 18:15 负责人张艺宝」→ 系统生成 3 条垃圾占位行（曝光选题1/2/3，负责人席小文），应为 1 条正确行（选题3/留资/张艺宝）；同时「我选择出脚本的选题你还能看到么」答非所问（dump 整版 5 个选题）。② 8/8 18:28「看一下表格@小席」→ 回「已发状态：未找到对应待发条目」——LLM 规划器把看表格误判成「确认已发布」并执行。前序迭代：2026-08-08《数据回流与已发布自然语言》（v1.6/v1.7）。

## 目标

① 排期指令能精确落到「刚定稿的那条选题」，不再编占位行；② 查「选中的/刚定稿」选题回刚定稿那条，不整版 dump；③ 标已发时日期笔误可容忍（唯一命中），撞题不猜；④ **意图识别不 100% 押在 LLM 单点**——最稳的意图（看表格/排期）走规则硬锚，高后果动作（确认已发布）加原文一致性防呆。成功标准：三条真群消息都回对（看表格→链接、排期→正确行、已发布→标已发）。

## 改动清单

**阶段 1：排期意图兜底 + 空占位守卫（Fix A/B/C，8/8 17:30）**
- `controller.py` 新增 `_parse_owner`（负责人/给/归+人名 解析）、`_list_reference`（第N条/个）、`_explicit_count`（N条/个）、`_has_schedule_intent`（日期/时间/今天明天下周/负责人/「排」字/params.date 任一命中）、`_parse_count`。
- `_try_pick_topic` ① 条件放宽：有 `_PASSED_HINTS` **或** 明确排期意图 → 用刚定稿选题（`_last_passed`），owner 走 `_parse_owner`；「第N个」「N条/个」显式排除（仍走②列表挑选/批量）。**`_last_passed` 是模块态，流水线被 sweep 后仍在——修复落点。**
- `_schedule_entries` 只服务批量排期：无明确数量（内容或 params.count）返回 `[]`，owner 不再写死席小文。
- `_exec_change_schedule`：`_schedule_entries` 空 → 明说「没指定排哪条选题或排几条」绝不编占位；成功回执补负责人。
- `_build_schedule_entry` 复用 `_parse_owner`。

**阶段 2：查选题答非所问（Fix D）**
- `controller.py` `_lookup_topic_record`：问的是刚选中/刚定稿那条（选+脚本/选择/出脚本/定稿/刚通过，`_asks_chosen`）→ 优先回 `_last_passed`/`_draft_ctx` 那一条，不回整版 dump。

**阶段 3：标已发日期容错（8/8 18:21）**
- `controller.py` `_resolve_publish_row` 返回 `(row, date_mismatch)`：日期对得上优先；对不上但标题在待产/待发行**唯一命中** → 容忍笔误（标记第二元素）；撞题歧义（多条同标题候选）→ 仍 None 不猜。
- 新增 `_publish_reply`：日期不符时回执注明「你报的日期 8/3 表里是 8/8，已按表里 8/8 确认」。

**阶段 4：意图识别防误判（8/9 09:22，核心）**
- `controller.py` Fix A 看排期表硬锚：`_VIEW_SCHEDULE_RE` + `_view_schedule_requested`（含排除词：改/结构/加一列/删/标已发/已发布/标成），`handle_message` 在 planner 前拦截——明确含「看/查/打开+表格词」或「表格词+链接」→ 直接走 `_exec_view_schedule`（复用 `_action_allowed` 权限 + `_schedule_reply` 链接回执），不依赖 LLM。
- `controller.py` Fix B 确认已发布防呆：`_PUBLISH_CONFIRM_WORDS`（已发布/已发/已确认发布/发布了一条/发布了/刚发布/刚发了/发了一条/发过了/发好了/发完了/发布完成/发出去了/这条发了/发了）+ `_has_publish_confirm` + `_publish_guard_reply`；动作命中处：action=确认已发布 但原文无确认词 → 不执行标已发，回「你是要标哪条已发布？说日期+标题」+ 排期表链接。
- `planner.py` Fix C prompt 加固：`_PLANNER_SYSTEM` 加「看表格/看排期 → 看排期表（立即给链接）」「确认已发布必须原话含『已发布/发了』等确认信号，光说『看一下表格/状态』不构成」。

## 架构影响

- **意图识别从「LLM 单点」改为「规则硬锚 + LLM + 防呆」三层**：最稳意图（看表格/排期）不走模型；高后果动作（确认已发布）模型判了也要过原文一致性校验。根子判断：LLM 单点判意图是脆弱架构，本迭代先把两个事故场景接回规则层，后续若其他动作也误判，同套思路扩展。
- 排期落行多了「排期意图兜底」路径：即使 `wait_schedule` 超时清掉、planner 没给结构化参数，`_last_passed`（刚定稿选题，模块态）也能被排期指令定位到，且无明确数量绝不编占位。
- 标已发从「日期严格匹配」改为「日期优先 + 标题唯一命中容忍笔误 + 撞题不猜」——保住了「不误标」初衷，只对笔误放行。
