# 迭代记录：意图识别 + 会话上下文连续性

> 日期：2026-08-02
> 类型：功能迭代（意图识别升级 + 多轮连续性）
> 对应决策：`需求与决策记录.md` §2.15

---

## 一、目标

解决主控路由单轮无状态的三个连续性场景：

1. 出选题后「第1个写条脚本」→ 席小文要知道第 1 个选题是啥，写针对性的稿。
2. 出内容后「这个脚本不行」→ 识别为修改，不是重写新稿。
3. 针对返回答案「为什么选这个角度」→ 归为针对性提问，不是闲聊。

RFC §11 验收剧本第 2 条（「第1个写脚本60秒」）与架构书 §7.1（「这个脚本不行」）早写了需求，代码一直没实现，本次补齐。

**用户硬要求**：意图识别必须带上下文，**7 轮上下文必带**；改动涉及旧文档先归档再改；迭代记录单独文件夹。

## 三、架构影响

- 主控调度职责增加：LLM 意图识别（带 7 轮上下文）+ 会话记忆（见架构书 §5、§7.2）。
- 大脑层模块新增：`session`（会话记忆）、`intent`（LLM 意图识别）。
- 专家接口扩展：`handle(task, context="")` + `explain(question, context="")`，上下文引用标注已实现（RFC §4）。
- 数据流补两步：读会话记忆 → 意图识别带上下文；本轮对话写回会话记忆（架构书 §12）。
- 错误处理新增：反馈修改/追问无上一条产出 → 明说失败（架构书 §13）。
- 触发形态新增第 3 种「上下文关联」（架构书 §7.2、PRD §7.1）。

**权限**：反馈修改/追问并入 admin-only（老板/产品），发片同事不可用。

### 真实 API 冒烟（DeepSeek）

意图识别（带 7 轮历史）：

| 输入 | 结果 |
|---|---|
| 帮我出3个选题 | 出选题 {count:3} |
| 第1个写条脚本 | 写脚本 {topic:普娃低分上名校, content_type:曝光} |
| 这个脚本不行，把开头改掉 | 反馈修改 |
| 为什么选这个角度 / 第2个的依据是什么 / 这个数据哪来的 | 追问 |

handle_message 端到端四轮：

```
round1 出选题 → 席小题出 3 个选题（带依据）
round2 第1个写条脚本 → 席小文按第 1 个选题（英语50分逆袭）写脚本
round3 这个脚本不行，把开头改掉 → 席小文带上下文改写（钩子加入打压替代）
round4 为什么选这个角度 → 席小文讲依据（引用「极致懂人性」「反常识劝退钩子」）
```

## 五、遗留

- 飞书群内实机验证（重启监听后群里实测三个连续性场景）。
- 历史进 prompt 的 token 成本：意图识别限定 7 轮、每行 200 字截断，专家 context 只取最近 2 轮；若 token 成本偏高，可缩轮数或截断更短，需按实际记账数据校准。
- 指代消解依赖 LLM 语义理解，认错对象时靠「最近一条专家产出」确定性回退兜底；后续可加显式指代锚点（如编号）进一步降低误判。
