# 迭代记录：小席规划器（主控改用大模型原生理解）+ 专家去约束化 + 改审核看法落地

日期：2026-08-07
关联：**生产事故**——老板发「需要@席小习 上线，第一次审核中"…两三万一个月工资…"是可以说的，要修改席小核的看法…」，小席却回复「命中『北大』属于合规红线」——一条与消息无关的 8/6 旧审核存档。老板质问：「能不能别走关键词这么局限，不能用大模型自己本身的语言理解能力啊…别为了这些内容让他们失去原本的能力啊」。前序迭代：2026-08-05《理解人话与说话即行动》（主控理解问题第一轮，提示词优化 +【行动】JSON 契约）。

## 目标

主控路由从「19 类意图表 + 关键词兜底链」换成**大模型原生语言理解**：一次 LLM 调用产出（自然回复, 可选动作），动作只在真需要系统落地时出现；知识库当参考不当考试答案，专家分工当视角不当枷锁。成功标准：那条事故消息 → 走「改审核看法」落规则，**不再**甩旧存档；老板口语任意说都能被听懂，而不是卡关键词。

## 改动清单

**阶段 0：止血（要理由不再误触旧存档）**
- `controller.py` `_show_review_reasons` 加双层门：仅当 `rounds` 最近一条席小核产出含「需要给您展示理由吗？」邀约锚点 **且** 当前消息 ≤8 字短回应含理由词才直发存档；长消息（如事故那条）不再误触发。删掉对裸「要」的裸信任。
- `handle_bot_output` 对**任意**席小核产出都 `split_review + context_store.save_review`（不只 wait_he 态），保证「要理由」读到的始终是最近一次审核，不读 8/6 旧存档。

**阶段 1：小席规划器（核心改造）**
- 新增 `planner.py`：一次 LLM 调用产出（自然回复, 可选动作）。末尾 `【行动】{"action":"<白名单>","task":"<规范任务>","params":{}}` 单行 JSON；非法/未知动作名 → 按无动作处理，不进聊天兜底乱发。温度 0.3 防非确定动作名。
- `controller.py`：主路径改 `_planner()`；`_ACTION_EXECUTORS` 分发表（动作名→既有执行器）；意图级权限 `_ADMIN_ONLY` → 动作级 `_PERMISSION_ADMIN`/`_PERMISSION_USER_READONLY`/`_THIRD_BUCKET`；`_pending_action` 存 `{"action","task","ts"}`；**任何流水线态活跃时 `action=None`**（含 wait_wen/wait_he/wait_fix），防规划器在自动改稿循环中途重复派单；动作命中时丢 planner 自然回复、执行器消息唯一（防双发）。
- 新动作「改审核看法」：老板纠正席小核判断/给审核标准 → 席小习提炼 → 直接落已确认规则，下次审核自动对齐。
- `intent.py`：删 `recognize()`/`INTENTS`/19 类 prompt；`by_keyword` 降级为 LLM 崩溃兜底（`_fallback_planner` try/except 包住 planner，失败时保证高信号指令不静默）。

**阶段 2：专家 prompt 去约束化 + 知识库参考化（只改引导性表述，承重锚点全保留）**
- `xiaowen.py`：「必须严格按以下格式，六大模块一个都不能少」→「参考以下结构，按主题自然组织，允许调整段落，第一行固定为 `## 脚本 vX`」；具体选题「必须严格写指定的那一条」→「优先写指定的那一条」；`【费用数据（唯一事实来源）】`→`【费用数据（事实参考，写作时核对）】`。
- `xiaoti.py`：依据「条数必须完全一致、严格一一对应」→「尽量按序号一一对应」；取材配额「必须一半一半、禁止全部来自单一来源」→「尽量兼顾两侧，别清一色只用一个来源」。
- `xiaone.py`：格式「必须严格遵守，别漏别改」→「锚点务必保留，其余按审核实际组织」；费用 framing 同步参考化。
- **承重锚点未动**：席小核首行三态结论 + `需要给您展示理由吗？` + `===审核详情===`（`_verdict_classify`/`split_review`）；席小文 `## 脚本 vX：标题`（`_SCRIPT_HEADER_RE`）；席小题 `序号.【类型】选题名` + `【依据】`（`_pick_item`）；席小核 REDLINES 本地红线拦截安全层不动。
- 未启用 `Desktop/提示词优化专家/` skill：其 rubric 偏「输出约束越严越高分」，与本轮去约束方向相反；本轮是保留锚点的手术式改写，直接改 + 测试锁锚。

**阶段 3：规则类型化 + 改审核看法落地**
- `rules.py`：加 `type` 字段（表达偏好/事实规则/内容策略/禁止事项，默认内容策略）；`add_rule`/`add_confirmed_rule` 加 `rtype` 参数；`render_rules` 按类型分组注入（顺序：禁止>事实>内容>表达，越靠前越硬守）；`load_rules` 兼容旧 6 列文件（无 type）回填默认类型，不丢旧规则。
- `xiaoxi.py`：JSON schema 加 `type`，提示「每条规则标一个 type…拿不准标内容策略」。
- `dispatch.py` `parse_learned_rules`：返回 (change, rule, type) 三元组，`learn_rules_flow` 透传 rtype。
- `controller.py`：`_exec_revise_review_rules`（改审核看法）透传 rtype 落已确认规则；`_resolve_doubt`（老板答复审核疑问拍板）落规则固定标 `事实规则`。

## 架构影响

- 路由模型翻转：**意图分类→死分支路由** 替换为 **一个会聊天会规划的主控**（`_planner` 一次调用产出回复+动作），意图表只在 LLM 崩溃时兜底。动作是白名单 + 分发表，模型只负责挑动作名，落地逻辑全复用既有执行器。
- 知识库/分工 framing 从「必须遵守/唯一事实来源」降为「参考资料、写作时核对」——专家恢复模型原生能力，垂类知识当增强不当约束。
- 规则从「一条例子被学成绝对真理」改为**类型化分组**：禁止事项最硬、事实规则要核对、内容策略/表达偏好是方向。老板拍板的两条路径（改审核看法、答复审核疑问）都**跳过待确认**直接落「已确认」，下次审核自动对齐。
- 权限从意图级降为动作级，同一动作在任何表述下权限一致；未知身份一律「当前身份未识别」。

- 单测全绿 **310 例**：controller 154 / intent 44（parse_plan 重构）/ planner 13（新）/ experts 31 / rules 11 / session 6 / material 6 / reflow 3 / circuit 5 / search 4 / scheduler 17 / pipe 5 / identity 5 / bots 5。

## 遗留

- `_pending_action` 仍是进程内存：小席重启后未确认的动作作废（与会话记忆同寿命，未变）。
- planner 动作白名单新增动作词时需同步扩 `ACTIONS`/`_ACTION_EXECUTORS`/`PERMISSIONS` 三处，否则动作名非法 → 按无动作处理（安全但可能丢高信号指令，待实测补词）。
- 去约束化后专家输出结构自由度上升，`_pick_item`/`split_review` 等锚点解析依赖 LLM 稳定保留锚点，长期观察锚点保真率。
- 规则 type 由席小习/改审核看法自由标注，可能标不准（如把表达偏好标成禁止事项）——render 顺序越靠前越硬守，误标「禁止事项」会过度收紧，后续可按实测引入老板校正入口。
