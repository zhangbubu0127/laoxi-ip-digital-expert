## 一、目标

用户提供两份源材料，要求新增知识目录「家长常问与成单解答」作为重要选题来源：
- 《常见提问 - Sheet1.csv》：8 大分类 × 核心关注点，50 条典型家长问题（含销冠回答）。
- 《结构化数据清洗工具/产出/知识库.csv》：165 条已成单顾问电话录音解答（问题/答案/标签/来源对话/顾问），标签=同一 8 分类体系。

并判断是否需要写入架构。**结论：需要**——知识库目录是架构书 §6 权威定义，专家读知识库靠硬编码 `load_file`，不加架构与代码，专家用不上新库。

## 三、架构影响

- 知识库事实层新增 1 个目录（9 文件），约 1.7 万 token 解答口径。
- 专家读知识库从「纯全量注入」升级为「关键词按需读取」：席小文按选题分类只读对应分类解答，控制 prompt token；席小题全量读问题清单（轻量）。
- **明确判断：不引入 LLM/RAG 读知识库**。知识库小、是唯一事实来源（漏检=事实错误）、RAG 需 embedding 依赖。正确演进=全量注入 → 关键词按需读取（本次）→ 将来量大了再考虑向量检索。

## 四、验证

1. `cd src && python3 -m brain.test_knowledge && python3 -m brain.experts.test_experts && python3 -m brain.test_controller` 全绿（test_knowledge 5 + test_experts 12 + test_controller 35）。
2. `load_qna` 冒烟：`load_qna("关于预算")` → 费用与价值分类；`load_qna("孩子英语差")` → 学术与能力；空 topic → 合并 8 分类。
3. `python3 scripts/build_qna_kb.py` 幂等重跑，165 条解答分类分布与源 CSV 标签一致、50 条典型问题不丢。
4. 全量回归 114 用例全绿（107 旧 + 5 test_knowledge + 2 test_experts）。

## 五、遗留

- `load_qna` 分类靠关键词匹配，选题 topic 不含关键词时兜底合并全部（token 较重）；将来可加更细粒度检索。
- 50 条 CSV 的销冠回答未重复入库（165 条录音解答已覆盖同分类口径）；如需销冠差异化说法可再补。
- 答疑/对话类脚本可直接引用成单解答；席小核审核口径已随费用数据.md 自动对齐，未额外改动。
