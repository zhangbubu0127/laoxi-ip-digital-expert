# 迭代记录：热点雷达升级——抖音小红书 Playwright 采集器 + 飞书写入

日期：2026-08-20
关联：雷达系统停跑 40 天（上次 2026-07-11），抖音只抓标题无热度数据，小红书无采集器。

## 目标

恢复雷达采集能力，升级热度数据质量：抖音抓真实点赞数+作者，新建小红书采集器抓点赞+收藏+作者，run.py 按平台分级热度写飞书。

## 改动清单

### 1. 抖音采集器升级（`scrapers/douyin_playwright.py`）

- 搜索 URL 加 `sort_type=1` 按点赞排序
- 重写 `_extract_videos()` JS：从 `a.innerText` 按行解析（时长/点赞/标题/作者），不再走卡片容器（之前走到 UL 导致所有视频共享同一个点赞数）
- 新增 `_parse_abbrev_num()`、`heat_douyin()` 热度分级（>=10万高/>=3万中/<3万低）
- 返回值从 `[(url,title)]` 改为 `[{url,title,author,likes}]`
- `_merge_output()` 写入真实热度数据：`"点赞3.3万·作者名"`

### 2. 小红书采集器新建（`scrapers/xhs_playwright.py`）

- 镜像抖音结构，差异：登录态 `.xhs_profile/`、节流 12-20s、热度分级（点赞+收藏>=5000高/>=1000中）
- 页面导航：`page.goto()` 直接访问搜索 URL 会超时，改为先到主页再 fallback 跳转
- DOM 提取：小红书笔记卡片无 `aria-label`、无 `img[alt]`、`<a>` 内无文字（图片布局），改为从 `card.innerText` 按行解析（标题/作者/日期/点赞数）
- 验证码处理：不设超时，等用户手动完成后自动继续

### 3. run.py 集成

- 新增 `heat_douyin(likes)`、`heat_xhs(likes, collects)` 平台热度函数
- `_load_tier()` 读取时检查扩展字段（`点赞数`/`收藏数`），有则重算热度
- 主流程分流：有真实互动数据的抖音/小红书条目同时进当天看板+长期库
- `write_daily()` 改为追加去重，不再清空重写
- 新增飞书群聊推送（`push_chat_id`）

### 4. 飞书 CLI

- 升级 lark-cli 1.0.81 → 1.0.88
- 重新授权：`--domain base` 获得 `base:table:create`、`base:field:update`、`base:record:create` 等完整权限

## 已知限制

- 抖音搜索结果页只有点赞数，评论/收藏/转发只在视频详情页，逐个采集不现实
- 小红书搜索结果页点赞=收藏（同一个数字），实际收藏数需进详情页
- CronCreate 提醒 session-only，7 天过期，Claude 退出后失效
