# 迭代记录：泛类内容素材化 + 完整讨论记录

> 日期：2026-08-02
> 类型：功能迭代（素材库 + 原文直传 + 完整讨论记录）
> 对应决策：`需求与决策记录.md` §2.16

---

## 一、目标

用户需求：发泛类内容（热点文章/竞品爆款/灵感），选题 bot 能结合已有知识库出选题。并确认 bot 是否具备「看完完整讨论记录」的能力。

查证现状：
- **完整讨论记录：无**。`session.py` 只存 bot 自己处理的最近 7 轮（内存、重启丢），每行截断 200 字；群里历史消息 bot 看不到。
- **泛类内容出选题有坑**：长文被 200 字截断；同一条消息里「贴内容+出选题」时原文被 `_topic_task` 丢弃；内容无持久化。

用户选最全档：**原文直传 + 素材库 + 完整讨论记录**。

## 三、架构影响

- 大脑层新增模块：`material`（素材库）、`history` 接缝（完整讨论）。
- 皮肤层新增模块：`group_history`（+chat-messages-list 拉群历史），注入大脑层接缝，维持「大脑层不直接调 lark-cli」解耦约束。
- 工作层新增目录：`workspace/素材/`（用户投喂泛类内容，只追加）。
- 席小题输入扩展：知识库 + 素材库 + 本条消息原文 + 最近群讨论。
- 触发形态新增「素材投喂」（架构书 §7.2、PRD §7.1）。
- 数据流新增：素材入库、出选题拉群历史（架构书 §12）。
- 错误处理新增：拉群历史失败/未接入降级（架构书 §13）。

**权限**：记素材/看完整讨论并入 admin-only（老板/产品）。

## 五、遗留

- 群内实测（用户触发）：贴泛类内容 +「记素材」→ 入库确认；「基于这些出3个选题」→ 席小题结合素材出题；「看完整讨论」→ 拉历史展示。
- 素材库 v1 只追加，不做修改/删除/合并；素材量大了可加按主题/来源整理。
- 群历史只取真人文本发言、最近 15 条、每行 150 字；若群很活跃可调窗口或加摘要。
- `pull_group_history` 每次调用 1 次 lark-cli 子进程 + 1 次 API 请求；出选题高频时可加短缓存。
