# 迭代记录：知识库语料分离（Part B）

日期：2026-08-05
关联：老板「说话逻辑、说话风格分开几个库来产出脚本，使用的时候让小席问一下」→ 架构变更，Part A（排期表修复）同日完成后接续落地。

## 目标

1. 说话逻辑/说话风格按用户分库（静态风格定义），不再只绑老席一个人设。
2. 出脚本时小席问「按谁的风格写」；同一聊天内已选风格复用；「按XX的风格写」可直接点名。
3. 反馈学习的规则按用户分库，不污染他人风格。
4. 通用知识（业务事实/家长画像/爆款规律/合规红线/案例库/家长常问/竞对分析）保持共享，不进风格库。

## 改动清单

- `knowledge/风格/老席/创作要求.md`：新建（复制自 `人设/老席创作要求会纪要.md`），老席默认风格库。
- `src/brain/knowledge.py`：B1 `load_style(user)`（缺省回落老席→老人设档案，绝不空）+ `style_users()`（扫 风格/ 子目录，老席兜底）。
- `src/brain/experts/xiaowen.py`：B2 `XiaowenExpert(generate, style_user="老席")`；`_system` 读 `load_style(self.style_user)` + `render_rules(style_user=...)`。
- `src/brain/experts/dispatch.py`：B2/B4 `split_style(task)`（剥离派单任务开头 `【风格:用户名】` 标记）+ `run_expert` 席小文/席小习按风格实例化；`learn_rules_flow(..., style_user)` 规则分库写入。
- `src/brain/rules.py`：B4 全部函数加 `style_user`；老席沿用 `memory/学习规则.md`，其余 `memory/学习规则-<用户>.md`。
- `src/brain/controller.py`：B3 `_last_style[chat]`（复用）+ `_requested_style`（「按XX的风格写」）+ `_write_script` 顶部守卫（`style_users()>1` 未指定 → `wait_style` 问风格）+ `_resolve_style`（答人名→登记→按原请求重派单）+ `_dispatch_expert` 对席小文/席小习非老席时给任务加 `【风格:用户名】`；B4 `_confirm_rules`/`_resolve_doubt` 按聊天最近风格路由规则库。
- `src/brain/controller.py` `handle_message`：新增 `wait_style` 分支（老板/产品答人名）。
- 测试：test_knowledge +4、test_rules +1、test_experts +1、test_controller +6。

## 架构影响

- **风格随行协议**：多 bot 形态下主控→专家bot 唯一通道是派单任务文本，故风格以任务开头 `【风格:用户名】` 标记传递，`run_expert`/`split_style` 剥离——单 bot 兜底与多 bot 同一套逻辑，不用另开通道。
- **分层不破**：计划原写「学习规则.md 放 knowledge/风格/<用户>/」，但知识库事实层只读是硬约束 → 风格库只放**静态**创作要求（只读，老板/运维建）；**动态**学习规则落 memory/（学习层），按用户 `学习规则-<用户>.md`。
- **规则分库路由**：反馈/学规则/确认按该聊天最近所用风格（`_last_style[chat]`，默认老席）落到对应库；席小文写作只读对应库已确认规则 → 不污染他人风格。
- **问风格只在多库时触发**：当前仅老席一个风格库 → `style_users()`=["老席"]，写脚本直接默认老席，不反问；老板日后建第二个 `knowledge/风格/<用户>/创作要求.md`，群内写脚本即自动先问用谁的。
- `_last_style` 是进程内存：小席重启后重置为默认老席，群内重新问一次即可；同一聊天内选过后复用。

## 遗留

- 风格库内容由老板/运维建（`knowledge/风格/<用户>/创作要求.md`）；规则分库文件由席小习/主控自动创建，无需手工。
- `_last_style` 进程内存不落盘：小席重启重置为老席默认；如需跨重启记住每个聊天的风格偏好，可后续把映射落盘（暂不做）。
- 圆桌/追问席小文场景未强制带风格标记（复用该聊天最近风格，`_dispatch_expert` 统一注入），行为一致。
