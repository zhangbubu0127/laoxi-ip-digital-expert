---

## 一、目标

用户反馈：「我说开圆桌会议智能体没有反应，是不是一个 bot 的设定还是不合理？」

查证现状（日志铁证，16:45）：
- **圆桌模式未实现**：`intent.py` 意图集没有「圆桌」，`controller.py` 没有圆桌派单分支（P2 一直空着）。
- **意图识别 LLM 截断 bug**：reasoning 模型把 400 个输出 token 全烧在「思考」上，长历史时没吐出 JSON 就 `finish_reason=length` → 降级关键词路由 → 消息「关于第二条选题，你开个圆桌会议」被「选题」二字误判成**出选题** → 回了一版新选题，用户视角「没理我」。
- **身份标签机制未生效**：`lark_bridge.run_loop` 发回复未用 `pipe.format_outbound`，所有回复裸文本无【席X】前缀——单 bot 靠文本标签区分身份的机制实际没工作。

结论：**不是单 bot 设定不合理**。架构 §8 本就设计单 bot 多视角并行（主控以多身份标签发消息），只是没实现 + 两个 bug 叠加。

## 五、遗留

- 圆桌 v1 采用「各自给一版、主控汇总成单条纪要」收敛形态；若要多专家独立连续发言体验，可改发多条标签消息（需防刷屏）。
- 圆桌 3 次 LLM 调用约 15-75s；高频使用可考虑并发或降配。
- 意图识别截断是概率性问题（max_tokens 800 后明显缓解但非根治）；长历史时可再观察，必要时裁剪历史或分块。
- 群里实测（用户触发）：「开圆桌会议」→ 【圆桌纪要】；确认所有回复带【席X】前缀。
