# 迭代记录：讨论上下文含智能体互话 + 派单上下文隐藏 + 席小题选题简洁 + 全角色对话

日期：2026-08-03

## 目标

老板三个体验问题：
1. 智能体互相说的话没进讨论上下文——真多bot 下给专家的上下文只有真人发言，丢了一半对话。
2. 派单消息把【上下文】大段贴进对话框，很乱——上下文应默默给专家看。
3. 席小题把选题依据直接甩出来、各角色只会回固定格式——要简洁、要能对话，但答完要绕回工作。

## 架构影响

- 大脑层仍不碰 lark-cli：上下文改走共享文件 + `_context_put` 接缝，测试可替换不落盘。
- 显示层干净（@ 消息只带任务）；内部信息走文件，读后删 + 过期清理，不留脏数据。
- 席小题「先选题后依据」是显示层拆分（专家输出仍含依据），依据按需回读，不重新生成。
- 全角色对话走主控路由：老板直接 @专家 → 主控带上下文回派该专家，保持单入口、专家仍只响应主控派单，无双响应。

## 遗留

- 老板群实测：① 问「看完整讨论」应能看到智能体互话；② 派单消息不再带【上下文】墙；③ 席小题先出选题再问「要不要看依据」，说「看依据」能回出依据；④ 跟小席说「今天被雨浇透了」应先共情（类似抱抱你的暖心话即可，不限定字面）再提议从淋雨角度出个选题；⑤ 直接 @某个专家闲聊应得到该角色共情+绕回工作。

## 后续修复（16:48）：依据追问「对不上」

老板反馈「追问席小题选题依据答得不好」「解释的原因不是他对应选题的原因，对不上」。三个根因全修：
- **模型在一个输出内序号漂移**：prompt 强制【依据】第 N 条=第 N 条选题，一一对应禁调换。
- **存盘只存依据不存题目**：`save_basis` 改存 (topics, basis) 配对，追问按题配对返回「选题N「题目」依据：…」，不再甩无题号的依据墙。
- **无存依据时重生成**：fallback 给 explain 且带上上次选题作上下文，避免重新生成一套对不上的依据。
