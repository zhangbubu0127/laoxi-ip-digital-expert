# 迭代记录：圆桌/写脚本逐步输出

> 日期：2026-08-02
> 类型：功能迭代（专家级逐步输出 v2）
> 对应决策：`需求与决策记录.md` §2.18

---

## 一、目标

老板反馈：「三个专家跑的时候可以有正在讨论的提示，或者有讨论的过程流式输出。」

查证约束：
- `llm.py` 是同步 urllib 调用，无流式接口。
- 飞书消息一经发出不可追加/编辑，token 级流式（打字机效果）在飞书不可行。

结论：选**专家级逐步输出**——每个专家产出一版立即发一条，不等全部生成完；配合开头「进行中」提示与结尾纪要收尾，讨论过程在群里实时可见。**写脚本流水线一并改逐步输出**，并顺手修掉一个旧缺陷：席小核此前审核的是占位文本，现在审核席小文真实稿。

---

## 二、改动清单

### 代码（src/）

| 文件 | 改动 |
|---|---|
| `src/pipe.py` | `OutboundMessage` 增 `emitted: bool = False` 字段：已即时发送的消息由 `run_loop` 跳过，避免重复发送；会话记忆仍完整记录。 |
| `src/brain/controller.py` | 新增皮肤注入接缝 `_emit = None`（即时发送 callable，大脑层不直接调 lark-cli）；新增 `_post(chat_id, replies, tag, text)` 帮助函数——`_emit` 注入时立即发送并置 `emitted=True`，否则追加 replies（测试/未注入场景退化）。圆桌 `_roundtable` 改逐步输出：先发【圆桌进行中】提示（含议题）→ 席小题/席小文/席小核各出一版即发 → 最后【圆桌纪要】收尾。写脚本分支改逐步输出：主控「写脚本进行中」→ 席小文出稿即发 → 席小核审核**席小文真实稿**即发 → 主控「流水线完成」收尾。 |
| `src/skin/lark_bridge.py` | `run_loop` 启动时注入 `_controller._emit`（经 `send_reply` + `format_outbound` 发带身份标签消息）；发送循环跳过 `reply.emitted`（已即时发过），只补发未发出的。 |

### 测试

- `test_controller.py`：`FakeExpert` 补 `last_task` 捕获（验证席小核收到的是席小文真实稿）；`tearDown` 复位 `_emit=None`（防串扰）；`test_roundtable_dispatches_three_views` 改为断言 5 条消息的 agent_tag 顺序；新增 `test_roundtable_streams_views_in_order`（注入 fake `_emit`，断言发送顺序 主控→席小题→席小文→席小核→主控，5 条全 emitted=True）、`test_write_script_streams_in_order`（断言顺序 主控→席小文→席小核→主控，且 `xiaone.last_task == "【测试】脚本 v1"` 证明审核真实稿）。

## 三、架构影响

- 大脑层新增能力：专家级即时发送接缝 `_emit` + `_post`，圆桌/写脚本从「全部生成完一次性发」升级为「边生成边发」。仍遵守「大脑层不直接调 lark-cli」——只调皮肤注入的 callable。
- 皮肤层职责不变：收发 + 身份 + 权限；即时发送仍是皮肤层动作。
- 写脚本流水线修复：席小核从审核占位文本改为审核席小文真实产出，审核闭环真实生效。
- 触发形态不变：圆桌讨论、写脚本；只是输出节奏从「汇总单条」变「逐条实时 + 首尾提示」。

## 五、遗留

- 逐步输出是专家级粒度，非 token 级流式（受 llm.py 同步 + 飞书不可编辑限制）。若未来要多 bot 独立账号，可天然多账号并行，各账号节奏更真实。
- 圆桌 3 次 LLM 调用约 15-75s，逐步输出期间是「一条一条到」而不是「一句话一句话到」；高频使用仍可考虑并发或降配。
- 群里实测（用户触发）：「开圆桌会议」→ 依次收到【圆桌进行中】→ 三个视角 →【圆桌纪要】；「写条脚本」→ 主控提示 → 席小文稿 → 席小核审核 → 主控完成。
