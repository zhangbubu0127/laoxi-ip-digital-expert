# 迭代记录：迁多bot（真多bot）

> 日期：2026-08-03
> 类型：架构迁移（单 bot → 6 独立飞书应用）
> 对应决策：`需求与决策记录.md` §2.21

---

## 一、目标

把单 bot（文本身份标签）升级为**真多 bot**：6 个角色各自独立飞书账号，主控 @派单，专家 bot 被 @ 时自触发输出。信息共享走「上下文随 @ 携带 + 共享只读知识库」。

用户追加两条飞轮编排要求 + 变更记录机制：
1. **写脚本流水线**：席小文出稿后，主控主动 @席小核 审核。
2. **修改飞轮**：老板/产品改稿 → 主控识别 → 立刻 @席小习 学差异写规则 → 席小习迭代席小题/席小文/席小核。
3. **数据飞轮**：老板报实际数据 → 主控识别 → 立刻 @席小盘 存档+分析+排期建议 → @席小题/@席小文 喂效果反馈学习。
4. **变更记录**：顶层规则加「改动前必读、改动后必记」，防上下文丢失。
5. 复盘 agent 改名 **席小盘**。

## 三、架构影响

- **皮肤/大脑解耦保持**：大脑层仍不直接调 lark-cli；`_dispatch_expert` 走皮肤注入的 `_emit`（@ 消息）+ `config/bots.json` 判定。
- **双模式兜底**：无 bots.json（单bot/测试环境）→ 进程内直接跑专家，旧行为零回归；配置后 → @ 异步派单。**129 用例全在兜底模式保持绿。**
- **信息共享**：上下文由主控写在 @ 消息的 `【上下文】` 段；知识库 `knowledge/` + 学习层 `memory/` 为共享只读文件，专家 bot 直接读。
- **写权限不变**：排期表主控唯一写；`memory/学习规则.md` 席小习写；`memory/数据回流.md`+`验证结论.md` 席小盘写。
- **两条飞轮闭环**：
  - 修改飞轮 = 老板改稿 → 席小习学差异 → 写规则文件（待确认）→ 席小题/席小文/席小核 prompt 都读 `render_rules()`。
  - 数据飞轮 = 报数据 → 席小盘存档+分析 → 写验证结论 → 主控回喂席小题/席小文 → prompt 读 `load_conclusions()`。
- **执行判断：排期建议不自动改表**。复盘结论是自由文本，自动解析改写排期表风险高（可能误改），故主控展示建议、留待老板 `改排期` 覆盖，符合「异常问老板」纪律。若后续要自动，需复盘输出结构化（JSON 排期动作）。

### 冒烟（兜底模式）

- 无 `config/bots.json` 时，主控 `出选题`/`写脚本`/`数据回流` 仍进程内输出（旧行为不回归）。
- 反馈修改 → 同时触发 席小文重写 + 席小习学规则（待确认）。

### 端到端（真多bot，待用户完成 Task 2 后）

6 进程全起（`--role` × 6），老板群里：
- 「帮我出个选题」→ 主控 @席小题 → 席小题输出选题。
- 「写条脚本，关于预算对比」→ 主控 @席小文 → 出稿 → **主控主动 @席小核** → 审核 → 汇总。
- 「8/3 预算对比 播放2.1w 留资23」→ 主控 @席小盘 → 存档+分析+建议 → **主控 @席小题/@席小文 喂效果反馈**。
- 老板改稿 → 主控 @席小习 → 写规则 → 席小题/席小文/席小核 prompt 生效。
