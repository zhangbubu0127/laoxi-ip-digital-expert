# 迭代记录：席小题接市场调研（实时搜索 + 带来源回答）+ 搜索源切 Tavily + 生成截断修复

日期：2026-08-08
关联：老板 10:50 起连续问「你能调研中本贯通么」「帮我了解一下北京国际中本贯通是什么」——系统当时只会出选题/闲聊，调研需求走不到专家。前序：2026-08-05《市场情报能力》（market.py 只做新加坡热点/竞对，Bing RSS 免 key）、2026-08-07《小席规划器与去约束化》（planner→controller 派单架构）。

## 目标

老板/家长在群里说「调研一下X」「帮我查查X」→ 小席主控识别为「调研」动作 → 派单席小题 → 席小题实时联网搜索 → 在群里给**结论先行、带来源、诚实区分「搜到的/无法确认的」**的调研回答。成功标准：一句话触发、一步成文、绝不编造、LLM 挂了也不静默丢搜索结果。

## 改动清单

- `brain/research.py`（新建）：调研流程。`research(question, top=5, generate=_default_generate)` → `_queries` 剥口语前缀（长词优先「帮我调研一下|调研一下|帮我查查|了解下最新…」）并按「和/与/、/，」拆连词成多条查询 → `market.search_web(q, sg_filter=False)` 实时搜索 → DeepSeek `_RESEARCH_SYSTEM` prompt 带来源成文（结论先行≤400字、明确区分「搜到的」和「无法确认的」、禁止编造）。无结果诚实回、生成失败回一手搜索结果、外层 try/except 永不 raise。
- `brain/market.py`：
  - `search_web` 加 `sg_filter=False`：非新加坡限定主题（中本贯通等）跳过新加坡关键词过滤。
  - **搜索源 Bing RSS → Tavily**：`search_web` 优先 `_tavily_search`（读 `config/secrets.json` 的 `tavily_api_key`，POST `api.tavily.com/search`，Bearer 认证，映射 title/url/content），无 key 或失败回落 `_bing_rss`。
- `brain/experts/xiaoti.py`：加 `research(question)` 方法，复用 DeepSeek generate，绕过选题 prompt。
- `brain/experts/dispatch.py`：`RESEARCH_MARK="【调研】"`，席小题 task 以 `【调研】` 开头走 `research()`。
- `brain/planner.py`：ACTIONS 加「调研」+ 判断段语义（老板要调研/查证市场信息→动作=调研，派席小题实时搜索后带来源回答）。
- `brain/controller.py`：`_exec_research`（从 task/params 取问题，`【调研】` 前缀派席小题，不设 pipeline）+ `_ACTION_EXECUTORS["调研"]` + `_INTENT_TO_ACTION["调研"]`；权限走 admin-only。
- `brain/intent.py`：`_RESEARCH_HINTS`（调研/市场调研/查查市场/了解下最新/什么行情/怎么运作…），放在「出选题」判断前，防「调研下这个选题」被出选题误吞。
- `src/skin/multi_main.py`：席小题「【依据】」主题拆分加 `not task.startswith("【调研】")` 守卫——调研输出不被拆选题。
- `config/secrets.json`：加 `tavily_api_key`（gitignored）。
- **第二轮（11:58）截断修复**：`llm.py` `finish=length` 无论正文空/有部分，一律并入「直接输出提示 + 加大预算重试（上限16000）最多 2 次」，不再对有内容截断直接 raise；`research.py` `max_tokens` 1000→3000、兜底文案「连不上模型」→「生成没成」（截断≠断网，不再误导老板）。

## 架构影响

- **搜索源从免 key 免费 API 变 SaaS key API**：Bing RSS 在中国网络路径被破坏（重定向 cn.bing.com 出垃圾结果）、DDG 被屏蔽；实测切 Tavily 后「中本贯通」返回真实相关结果。key 只进 gitignored 的 `config/secrets.json`，`market.py` 无 key 时自动回落 Bing RSS，老功能（热点/竞对）不受影响。
- **调研是异步派单流水线，不设 pipeline**：主控 `_dispatch_expert` 发 @mention 派单后返回，由席小题进程自触发回复——和出选题/写脚本同一派单通道，但无 wait_* 状态机（调研一次性回答，无需多步确认）。
- **调研回答唯一特殊处理点**：`multi_main.py` 席小题分支对 `【调研】` 前缀跳过选题拆分逻辑——这是皮肤层与大脑层分离后，唯一一处按任务标记在皮肤层做的分支（不破坏「皮肤层不做业务判断」：它只做「不拆成选题」的格式守卫）。
- **llm.py 截断语义变更**：`finish=length` 从「硬错误」变「自动重试」，全局受益（planner/写脚本/审核同样会撞）；已确认无调用方依赖原 raise 行为。重试上限 16000 token 兜底，仍失败才 raise。
