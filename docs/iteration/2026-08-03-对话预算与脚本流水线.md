# 迭代记录：对话预算拉高 + 席小文固定格式 + 审核自动改正 + 已读表情

日期：2026-08-03

## 目标

老板五个体验问题：
1. 小席接话偶发「退回模板」——DeepSeek 推理型模型先出 `reasoning_content` 再出正文，`max_tokens` 是推理+正文总上限，预算太小被思考吃满 → content 空 → 降级模板。
2. 审核意见要直接 @文章、文章去改正，别只停在「展示意见」。
3. 席小文脚本输出格式不固定，老板指定六段式固定模板。
4. 机器人收到消息后要在消息下面出现已读表情（用户点名「奋斗」）。
5. 重启 bot 时旧进程没杀干净，两套小席同时消费同一群事件，连回两条。

## 改动清单

- `src/brain/llm.py`：空内容（任意 finish）逐步加大 max_tokens 重试 3 次（×2 封顶 16000），仍空才抛；length 且有内容才判真截断。修「退回模板」根因。
- `src/brain/controller.py`：
  - `_default_chat_generate` max_tokens 200→800→**10000**（调研后拉高）+ system 加「直接给最终答复，不要输出思考过程」。
  - 写脚本流水线审核自动改正：席小核判定含 需改/红线/黄线/❌ → 主控直接 @席小文「修改这条脚本」→ step wait_he→wait_fix→复审 wait_he 闭环，最多 2 轮（`_MAX_FIX_ROUNDS`），仍不过改请老板定夺；新增 `_verdict_needs_change` 判定。
- `src/brain/experts/xiaowen.py`：脚本输出改老板指定固定格式六段：`【席小文】## 脚本 vX：标题` + 【口播正文】+ ## 结构拆解（时间段|内容|目的 表）+ ## 封面文字（主封面3选1）+ ## 钩子词（投放/评论区关键词）+ ## 投放建议（人群定向/投放策略/转化路径/已验证规律）；版本号修改递增 v1→v2。
- `src/skin/multi_main.py`：去掉 `_strip_self_tag`（席小文脚本格式头【席小文】得以显示）。
- `src/skin/lark_bridge.py`：新增 `add_reaction(chat_id, message_id, emoji, profile)`（lark-cli im reactions create），`_READ_EMOJI="STRIVE"`（飞书原生「奋斗」，实测 6 候选 emoji_type 后选定：MUSCLE/SALUTE/STRIVE 有效，FIST/FIGHT/FIRE/GO/DETERMINED/FIGHTING 无效）；run_loop 收到真人消息即加已读表情（处理前），专家 bot 触发派单时也对 @ 消息加（profile=自身）。

## 对话预算调研结论（为何 10000）

- deepseek-chat（非思考模式）max_tokens 上限 8K；deepseek-reasoner（思考模式）默认 32K / 上限 64K。
- 社区项目常见 2K–8K；DeepSeek-Reasonix 对 Chat 端点默认发 32768 保守预算。
- 本项目模型 `deepseek-v4-flash` 为推理型，预算 10000 在安全区间内，配合 llm.py 空输出自动加预算重试，聊天接话不再掉模板。

## 架构影响

- 大脑层仍不碰 lark-cli：已读表情由皮肤层 `lark_bridge.add_reaction` 调 lark-cli，经注入接缝。
- 审核自动改正是编排状态机扩展（wait_he→wait_fix），未新增专家，仍在 `_dispatch_expert` 双模式内。
- LLM 稳定性提升是 `llm.py` 客户端行为 + 预算参数，不涉模型/密钥改动。
