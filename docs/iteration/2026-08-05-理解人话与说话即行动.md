# 迭代记录：理解人话 + 说话即行动（提示词优化 + 最小代码契约）

日期：2026-08-05
关联：老板反馈「智能体太不够智能」——例子：老板问「刚才的选题你还能看见么」，小席回得暖心但没真核对、没派单，只是空话。用提示词优化专家技能（`/Users/User/Desktop/提示词优化专家`）做，老板拍板「架构级放开」。前序迭代：14:00 存档持久化（basis 不被 sweep）、14:10【提议】标记闭环。

## 目标

6 个 agent（小席主控 + 5 专家）像人一样理解口语、做垂类专属工作；对话里承诺的下一步真执行——「承诺即兑现」，不再停在话术。成功标准：老板问「刚才的选题你还能看见么」→ 真核对存档并给回执；小席/专家提议下一步、老板点头后真派单。

## 改动清单

**第一层：意图识别（认识「查记录」）**
- `src/brain/intent.py`：INTENTS 增「查记录」；LLM 意图提示词补「刚才/上次/之前 + 回顾性动词 → 查记录，不是闲聊、不是出选题」；`by_keyword` 加 `_LOOKUP_HINTS` 兜底（能看见/还能看到/还在/在哪/哪去了/丢了/回顾…，判定放「选题→出选题」之前），用例防误伤「把刚才那个选题写条脚本」仍走写脚本。

**第二层：执行契约（说到做到）**
- `src/brain/controller.py` 新增【行动】JSON 协议（机器可解析承诺）：
  - `_ACTION_RE`/`_ACTION_INTENTS`/`_register_actions`/`_run_immediate`/`_register_action_pending`/`_strip_action_lines`
  - `when:"立即"`（核对选题记录/看排期表）→ `_run_immediate` 当场真执行，把回执补进回复；
  - `when:"待确认"`（重新出选题/写脚本/审核脚本）→ 登记 `_pending_action`，老板回「好/要/可以」真派单；
  - `_chat_reply` 登记后从展示剥离行动行（老板看到自然话术）。
- **专家提议拾取**：专家被直接 @ 闲聊自回时，建议的可执行下一步带【动作名】标记（例「要不要我【重新出选题】按预算方向出 3 个？」）→ `_register_expert_proposal`（`_EXPERT_ACTION_RE`）识别登记；覆盖单进程直接 @ 路径（`_route_intent`）与多 bot 自回路径（`handle_bot_output`）。
- **查记录路由**：`_route_intent` 加「查记录」分支直通 `_lookup_topic_record(force=True)`；`_TOPIC_LOOKUP_PAIRS` 拓宽（含「能看见」变体）；`force` 参数；修正「存档 10 分钟清理」误导文案 →「只留最近一版」（basis 存档 14:00 起已持久，sweep 不碰）。

**第三层：专家提示词（理解人话）**
- 五个专家（xiaoti/xiaowen/xiaone/xiaoxi/fupan）各补「理解老板的话」few-shot：老板口语 → 垂类任务的正确理解（例：席小盘「这条怎么这么差」→ 看数据找原因不是安慰），不删任何已认可规则；闲聊建议下一步用【动作名】标记。
- 席小核/席小习/席小盘严格不动解析依赖的输出格式（审核结论三段/规则 JSON）。

## 架构影响

- 小席闲聊提示词升级为「说话即行动契约」：从 2.26「闲聊不承诺」、14:10「提议必须带标记」升级为「**承诺即兑现**」——把承诺建模成代码可解析的 JSON 契约，让承诺在代码层有出口，不靠模型自觉。
- 14:10 的【提议】prose marker 保留作兼容层（`_register_proposal` 仍在），新契约【行动】JSON 优先。
- 14:00 的 basis 存档持久化成为「查记录」的数据根：立即核对当场回执真实选题清单。
- 意图识别 + 行为契约 + 专家提示词三层分工：识别层漏词走代码兜底（`_LOOKUP_HINTS`），行为层不执行走契约解析，专家理解靠 few-shot。
