# 迭代记录：说到做到（查记录真核对 + 存档持久化 + 提议→肯定→真执行闭环）

日期：2026-08-05
关联：老板反馈「小席说这些话是否真去做了？没有的话希望它真做，不要光给答案就停」「这类不执行动作的想法很好，能不能问完我、我给肯定答复时它真执行」→ 两个递进需求。

## 目标

小席说出口的动作必须真做：老板问「刚才的选题还能看到么」→ 真核对存档/记忆回执真实清单；小席聊天里提议的下一步（重出选题/写脚本/审核）→ 老板点头后真派单真执行，不再停在话术。

## 改动清单

**第一层：存档持久化（数据根）**
- `src/brain/context_store.py` `sweep()`：跳过 `_basis.json`/`_review.json` 存档（与 `take()` 排除对齐），只清临时派单上下文。根因：`lark_bridge` 每轮调 `sweep(600)`，把席小题三次 basis 存档全清掉，`workspace/上下文/` 全空 → 想核对也无从核对。

**第二层：查记录真核对（行为）**
- `src/brain/controller.py`：`_TOPIC_LOOKUP_PAIRS` 触发词 + `_lookup_topic_record()`——识别「查/核对选题记录」类请求（选题+看到/还能看到/还在/记录/原始/丢/回顾/哪去了…）→ 真读 basis 存档 → 有则回执真实选题清单（含类型标签）；无存档但有会话记忆席小题产出 → 回执记忆里的；无存档但方向可恢复 → **真实派单席小题按方向重出一版**；都无 → 如实说没找到 + 引导老板给方向。

**第三层：提议→肯定→真执行闭环（老板本迭代核心需求）**
- 小席闲聊 prompt（`_default_chat_generate`）规定：提议下一步必须句末加固定标记【提议】<动作>：<内容>；动作限 出选题/重新整理选题/写脚本/审核脚本/看排期表。
- `_chat_reply` 改走 `_register_proposal` + `_strip_proposal_marker`：解析标记登记 `_pending_action[chat_id]`（intent/params/task/ts，3600s 过期），对外剥离标记展示自然话术。
- `handle_message` 插入肯定语检查：wait_boss 挂起之后、确认已发布之前——老板/产品回短肯定词（好/要/可以/行/嗯…8 字内）且无未决规则 → `_pop_pending` 命中 → `_route_intent` 真执行。无待定动作时不劫持肯定词。
- 派单/排期/素材/圆桌等原 inline 分发链抽成 `_route_intent(msg, result, rounds, replies)`，提议确认与正常意图共用同一执行链。
- **动作白名单防垃圾**：`_PROPOSAL_INTENTS` 删掉 `("排期","改排期")`——改排期需具体日期选题，聊天锁定不了，肯定回复会把细节丢成「好」→ 落占位垃圾（复用 12:35 修复的教训）。2.26「闲聊不承诺契约」升级为「提议必须带标记，带标记=承诺、无标记=纯话术」。

## 架构影响

- 存档（basis/review）成为固定记录：sweep 永不删、被新产出覆盖（有界）；临时派单上下文仍 10 分钟清理。老板随时能核对到选题清单。
- 「说到做到」从口头承诺升级为结构性保证：小席提议只有带【提议】标记才会被登记、被肯定后真执行；无标记的闲聊永远只是话术，不冒充已执行。
- 肯定语触发是主控级（仅老板/产品），且严格卡在 wait_boss（审核疑问 @老板）之后——挂起的疑问优先解决，不被新提议顶掉。

## 遗留

- `_pending_action` 是进程内存，小席重启后未确认的提议作废（与会话记忆同寿命）；已确认的执行路径不吃亏，只有「提议后重启前没确认」的窗口会丢。
- 提议细节依赖 LLM 输出质量：出选题的「方向」来自标记内容，若老板原话信息量不足，席小题拿到的是模糊方向（与 2.26 派单重出同一局限）。
