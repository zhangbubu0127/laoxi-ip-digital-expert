## 1. 老板只要「选题四的依据」，小席回全部依据

**老板反馈**：测试群 14:26 发「给我选题四的依据」，而 14:25 席小题刚出 5 条选题 + 存档依据 → 小席回**全部**依据，开头还写「第 N 条对应第 N 个选题」。

**根因**：`_ask`（controller.py 1128 起）speaker==席小题 且有 basis 时直接 `load_basis` 全部 dump，不解析「选题四」序数——序号解析逻辑只在皮肤层 multi_main 有，controller 没复用，皮肤/大脑各维护一套。

**整改**：新建 `src/brain/basis.py` 公共序号解析模块（`match_index`/`numbered_topics`/`basis_map`/`paired_topics`/`item_reply`，从 multi_main 迁出，多 bot 暂不动皮肤层降回归风险）；`_ask` 命中序数 → 只回 `选题{n}「{题目}」\n依据：{reason}`；序号解析不到 → 仍回全部依据兜底，不丢功能。

**验证**：test_controller 181→184（`test_ask_basis_picks_nth` / `test_ask_basis_fallback_all_when_no_index`）；真群待复测「给我选题四的依据@小席」只回第 4 条。

## 2. 老板用自己语言改脚本，席小习能不能拆解学习 + 对比哪里有不同

**老板反馈**：问「我用我自己的语言修改脚本时候，席小习有拆解并学习到的能力么」，追加「还要能对比到哪里有不同」。

**先更正一个判断**：多 bot 模式下席小习学习落库**其实是通的**——席小习在自己进程里 `learn_rules_flow → rules.add_rule` 落「待确认」，老板回「确认」→ `confirm_pending` 落「已确认」。此前误报「断链」，实际不是。真正的病灶有两处。

**根因**：
1. `_resolve_doubt`（wait_boss 拍板路径）老板给实质答案（如「早三年吧」）时，只 `add_confirmed_rule` 落一条「答案原文」规则 + 派席小文改稿，**席小习完全不参与拆解**——而老板用自己的语言改稿，最常走的正是这条路径。
2. `_revise` 路径席小习拿到的对比素材不足（旧稿 + 一句话要求），且 prompt 没锁「对比哪里有不同」的输出契约——完整改后稿和一句话要求是两种不同能力，混在一起容易要么给不出 diff 要么编造 diff。

**整改**：
- `_resolve_doubt` 拍板答案后**同步**派席小习拆解（复用 `_exec_revise_review_rules` 单 bot 同步模式，不走 `_emit` 派单、不引入二次确认）：`{answer}\n把老板这段确定答案拆解成审核/写作规则` → `parse_learned_rules` → `add_confirmed_rule` 落「已确认」。失败只记日志，不阻塞主流程。
- xiaoxi.py prompt 锁两条输出契约：完整改后稿 → **先逐点列差异（AI原版 X → 老板改后 Y）再提炼规则**；一句话要求 → 直接提炼规则并明说「给不出逐句对比」，不编造 diff。

**验证**：test_controller 新增 `test_resolve_doubt_learns_via_xiaoxi`（拍板答案 → 席小习拆解规则落「已确认」）；真群待复测——跑流水线出审核疑问，老板回实质答案后，规则库出现席小习提炼的拆解规则（可发「看已确认规则」抽查）。
