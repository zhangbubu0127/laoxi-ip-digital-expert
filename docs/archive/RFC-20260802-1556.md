# 老席留学IP数字专家 · RFC（技术方案）

> 版本：v1.0 · 2026-08-01
> 状态：设计评审稿
> 配套文档：`需求与决策记录.md`（决策）、`架构书.md`（架构）、`PRD.md`（产品）
> 本 RFC 面向工程实现，描述模块边界、接口契约、数据流、迁移路径。

---

## 1. 目标与非目标

### 目标
- 在飞书群实现多专家协作的内容生产系统（曝光/留资/信任三引擎）。
- 本机用 lark-cli 单 bot 跑通最小闭环。
- 皮肤层/大脑层解耦，为迁多 bot 铺路。

### 非目标（v1 不做）
- 不接入短视频平台发布。
- 不做投流/账号矩阵执行（真人运营）。
- 不做独立 Web/App 界面。
- 不做真正的多 bot（v1 单 bot，迁移路径见 §7）。

## 2. 模块边界

```
┌──────────────────────── 皮肤层 ────────────────────────┐
│  lark_cli_bridge                                       │
│  ├─ listener: im.message.receive_v1 事件订阅            │
│  ├─ sender:   messages_send（文本/标签）                │
│  ├─ identity: 从 event.sender 解析 open_id → 角色映射    │
│  └─ guard:    权限拦截（老板/发片同事）                   │
└──────────────┬─────────────────────────────────────────┘
               │ 管道协议（见 §3）
┌──────────────┴─────────────────────────────────────────┐
│  大脑层 main_controller                                │
│  ├─ router:     触发形态判定（定向/意图/排期/默认）        │
│  ├─ scheduler:  排期表读写（唯一写权限）                 │
│  ├─ circuit:    token 记账 + 熔断                      │
│  ├─ dispatcher: 派单给各专家                            │
│  └─ roundtable: 圆桌模式编排                            │
└──────────────┬─────────────────────────────────────────┘
               │
     ┌─────────┼─────────┬─────────┬─────────┐
     ▼         ▼         ▼         ▼         ▼
  席小题     席小文     席小核     席小习    复盘agent
  (选题调研) (写手)    (审/核/外搜) (学习)   (数据回流)
     └─────────┴─────────┴─────────┴─────────┘
               │ 读写
               ▼
   knowledge/  workspace/  memory/
```

## 3. 管道协议（皮肤↔大脑接口）

每次群消息进出，皮肤层与大脑层通过统一消息结构传话：

```json
{
  "id": "msg_20260801_0001",
  "chatId": "oc_xxx",
  "sender": { "openId": "ou_xxx", "role": "老板|发片同事" },
  "content": "帮我出3个选题",
  "isAtBot": false,
  "atNames": ["席小题"],
  "timestamp": "2026-08-01T10:00:00+08:00"
}
```

大脑层 → 皮肤层的回执统一为：

```json
{
  "id": "msg_20260801_0001",
  "replyText": "【席小题】推荐3个选题：…",
  "tags": ["席小题"],          // 身份标签，单bot用前缀区分
  "sendTo": "oc_xxx",
  "tokenCost": 12345
}
```

**契约约束**：
- 皮肤层只做收发 + 身份解析 + 权限拦截，不做业务判断。
- 大脑层不直接调 lark-cli，只经皮肤层。
- 解耦意味着：换多 bot 时只重写皮肤层，管道协议不变。

## 4. 各专家模块接口

每个专家统一暴露一个「接单函数」，主控调度按需调用：

```
Expert.handle(input) -> output
input:  { 任务类型, 内容, 上下文引用, 身份 }
output: { 产出文本, 标签, 需老板确认? , 置信度?, 状态 }
```

### 席小题（选题调研）
- 输入：需求（角度/数量/类型偏好）
- 输出：选题清单（每条带类型标签+调研依据）
- 依赖：知识库 knowledge/ + 热点/竞品调研
- 失败：调研源不可用 → 知识库兜底，标「调研降级」

### 席小文（写手）
- 输入：选题 + 风格档案引用
- 输出：脚本 vN（含拆解/封面/钩子/投放建议）
- 依赖：knowledge/ 业务事实 + style/ 风格
- 失败：审核退回 → 按原因重写

### 席小核（审核核实）
- 输入：脚本 + 知识库
- 输出：判定（红线/黄线/通过）+ 外搜结果（来源/置信度）
- 依赖：knowledge/ 合规红线 + WebSearch
- 失败：不确定事实 → 返回「需老板确认」挂起

### 席小习（反馈学习）
- 输入：AI原版 + 老板修改稿
- 输出：提炼规则 + 确认询问
- 依赖：memory/ 规则库
- 失败：老板否 → 丢弃并记录被否规则

### 复盘agent（数据回流）
- 输入：排期表「已发」条目
- 输出：数据回流 + 验证结论 + 排期调整建议
- 依赖：笔记API / 人工 + memory/
- 失败：数据缺失 → 标「待回流」催补

## 5. 排期表实现

本机用 Markdown 文件 `workspace/排期表.md`，主控唯一写权限。

```
| 日期 | 内容类型 | 选题 | 目标 | 状态 | 负责人 | 数据回流 |
```

**状态机**：`待产 → 审核中 → 待发 → 已发（人工确认）→ 回流完成`

**已发人工确认流程**：
```
排期表条目「待发」
  → 发片同事在群发「8/3已发布」
  → 皮肤层识别 sender.role == 发片同事
  → 大脑层校验该条是否待发
  → 标「已发」+ 记数据回流为「待回流」
  → 回群确认
```

## 6. 数据回流实现（双轨）

| 来源 | 方式 | 阶段 |
|---|---|---|
| 笔记API | 定时/触发拉平台数据 | 先验证替代性 |
| 人工兜底 | 发片同事群内回填 | 一直保留 |

流程：`已发 → 等数据 → （API拉取 或 人工回填）→ 写 memory/数据回流.md → 复盘agent分析 → 通知主控调排期`

## 7. 迁移路径（单bot → 多bot）

**关键：只换皮肤层，管道协议、大脑层、存储层全部复用。**

| 项 | 单bot（v1） | 多bot（v2） |
|---|---|---|
| 事件监听 | 1个（应用A） | 6个（各专家应用） |
| 身份呈现 | 【席X】文本标签 | 独立账号 |
| 凭证 | 1个app | 6个app（config bind --app-id） |
| 管道协议 | 不变 | 不变 |
| 大脑层 | 不变 | 不变 |
| 存储层 | 不变 | 不变 |

**迁移动作清单**：
1. 建 5 个专家自建应用（席小题/小文/小核/小习/复盘）+ 1 个主控应用。
2. 各自 `config bind --app-id`。
3. 皮肤层每个 bot 订阅自己的事件，路由到对应专家。
4. 回执不再拼文本标签，各 bot 用自己身份发。
5. 权限/熔断/排期逻辑零改动。

## 8. 错误处理与兜底

| 异常 | 处理层 | 行为 |
|---|---|---|
| 触发识别不出 | 大脑 | 回「需要我做什么？…」 |
| 专家超时 | 大脑 | 重试1次，仍失败回群明说 |
| 知识库查不到 | 席小核 | 发群 @老板，挂起 |
| 外搜拿不准 | 席小核 | 标低置信度，发群问 |
| 审核红线 | 大脑 | 退回席小文重写，不秀失败稿 |
| 数据缺失 | 复盘 | 标「待回流」，催补 |
| token 临近熔断 | 大脑 | 提前报告 |
| 圆桌失控 | 大脑 | 中断→各自一版主控汇总 |
| 越权 | 皮肤 | 拦截提示 |

**兜底原则**：异常一律「问老板」或「明说失败」，绝不静默、绝不编造。

## 9. 熔断与 token 记账

- 大脑层每次调用记录 tokenCost，累计入账。
- 阈值：默认 1 亿 token（可配置）。
- 达到阈值：熔断 → 回群报告消耗 → 建议暂停/降配 → 等待老板指令。
- 熔断状态持久化，重启不丢失。

## 10. 实现顺序（与 PRD P0 对齐）

1. 皮肤层 lark_cli_bridge：收消息 / 发消息 / 身份解析 / 权限拦截（最小版）。
2. 管道协议：定义消息结构 + 回执结构。
3. 大脑层 main_controller：路由 + 派单 + 排期表读写 + token记账。
4. 专家基础版：席小题 / 席小文 / 席小核（流水线三件套）。
5. 闭环验证：老板说写脚本 → 出稿 → 审核 → 回群 → 排期表更新。
6. P1：席小核外搜 + 席小习学习 + 复盘数据回流。
7. P2：圆桌模式、迁多 bot。

## 11. 验收剧本（本机阶段）

1. 群消息「帮我出3个选题」→ 回席小题选题清单（带类型标签）。
2. 「第1个写脚本60秒」→ 回脚本v1 + 审核结论。
3. 「看排期表」→ 回当前排期表。
4. 「下周三要3条曝光」→ 排期表加3条曝光 bossOverride。
5. 发片同事身份「8/3已发布」→ 状态待发→已发。
6. 贴改稿 → 席小习提炼规则并求确认，确认后写入。
7. 越权：发片同事「改排期」→ 拦截提示。
8. 熔断：临时设小阈值 → 触发报告。
