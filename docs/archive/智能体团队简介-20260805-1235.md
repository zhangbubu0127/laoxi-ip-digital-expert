# 老席留学IP数字专家 · 智能体团队简介

> 版本：v1.0 · 2026-08-01
> 用途：飞书 bot 简介配置、团队协作说明、架构参考

## 团队总览

一个小席 + 五个专家，共六个角色。群聊形态下，小席负责编排，五个专家被派单才发言（除圆桌模式）。

| 角色 | 身份标签 | 一句话定位 | 归属 |
|---|---|---|---|
| 小席 agent | 【小席】 | 群聊路由 + 排期 + 熔断 | 大脑层顶层 |
| 席小题 | 【席小题】 | 选题 + 调研合体 | 专家 |
| 席小文 | 【席小文】 | 写手，内嵌风格 | 专家 |
| 席小核 | 【席小核】 | 审核 + 核实 + 外部搜索 | 专家 |
| 席小习 | 【席小习】 | 反馈学习，自我迭代 | 专家 |
| 复盘 agent | 【复盘】 | 数据回流，飞轮闭环 | 专家 |

## 1. 小席 agent（顶层）

- **身份标签**：`【小席】`
- **职责**：
  - 接收群消息 → 读会话记忆(7轮) → LLM 意图识别（带上下文）→ 判断触发形态 → 派单 → 逐步输出 → 发回群
  - 管理排期表（唯一写权限）
  - 会话记忆：按 chat_id 保存最近 7 轮对话，跨轮消解「第1个」「这个脚本」等指代
  - 素材库：记素材入库（workspace/素材/），出选题时读素材库
  - 完整讨论：皮肤层拉最近群历史，出选题 /「看完整讨论」时使用
  - 圆桌讨论：抽议题 → 【圆桌进行中】提示 → 派席小题/席小文/席小核三视角逐条实时发 → 【圆桌纪要】收尾
  - 写脚本流水线：主控提示 → 席小文出稿即发 → 席小核审核即发 → 主控完成提示
  - token 记账与熔断
  - 知识检索
- **触发形态**（同时存在，不互斥）：
  1. 显式：@agent名 + 需求
  2. 隐式：说「写脚本/出选题/审核」→ LLM 识别意图（带 7 轮会话记忆）
  3. 上下文关联：说「第1个」「这个脚本」「为什么选这个」→ 消解指代（反馈修改/追问找最近一条专家产出）
  4. 定向：说专家名字 → 只派该专家
  5. 默认：无触发 → 回「需要我做什么？出选题/写脚本/看排期/讨论？」
- **发言权**：随时在场，兜底接话。
- **路由表**：

| 老板说 | 主控做什么 |
|---|---|
| 帮我出个选题 | 派单席小题 |
| 写条脚本，关于XX | 流水线：席小题→席小文→席小核 |
| 看下排期表 | 贴出排期表 |
| 下周三要3条曝光内容 | 改排期表，标记任务 |
| 大家讨论下XX | 触发圆桌模式 |
| 这个脚本不行 | 反馈修改：找最近一条专家产出，路由给产出者改写 |
| 为什么选这个角度 | 追问：找最近一条专家产出，路由给产出者讲依据 |
| 第1个写条脚本 | 上下文关联：读上轮选题，派席小文写第1条 |
| 记素材：<内容> | 存入素材库 workspace/素材/ |
| 更新情报/搜竞对/现在什么话题热 | 更新市场情报：market.refresh() 实时搜热点+竞对线索（尽力而为）→ 写竞对分析/热点话题.md + 竞对线索.md，回执条数 |
| 看完整讨论 | 皮肤层拉最近群历史并展示 |
| 开圆桌会议 / 大家讨论下X | 抽议题 → 【圆桌进行中】提示 → 席小题/席小文/席小核三视角逐条实时发 → 【圆桌纪要】收尾 |
| 席小题，换选题方向 | 定向派席小题 |

## 2. 席小题（选题 + 调研）

- **身份标签**：`【席小题】`
- **职责**：选题 + 调研合体。基于知识库 + 素材库（用户投喂泛类内容）+ 最近群讨论 + 市场调研（平台热点/竞品爆款/家长痛点），选出热点选题。
- **市场情报能力（2026-08-05）**：`_system()` 注入【竞对情报/市场热点】段——竞对图谱 + 中新教育对比（人工润色）+ 雷达热点话题（`scripts/sync_radar.py` 机器覆盖）+ 竞对线索（「更新市场情报」refresh 存）。出选题「各出一半」配额：约一半取材市场情报段、一半取材本地知识库，每条依据标注来源（市场热点/竞对/知识库），杜绝单一来源。
- **关键设计**：调研是选题的组成部分，不单设独立调研角色。
- **输出**：选题清单，每条带类型标签（曝光/留资/信任）+ 调研依据。
- **发言权**：被派单才发言。
- **失败处理**：调研源不可用 → 知识库兜底，标「调研降级」；选题被老板否 → 记录否因，下次避开。

## 3. 席小文（写手）

- **身份标签**：`【席小文】`
- **职责**：基于选题 + 知识库 + 风格档案产出多版文案。内嵌风格（含原「席小风」职责——风格是写作约束，不是独立环节）。
- **输出**：脚本 v1/v2…，附结构拆解、封面文字、钩子词、投放建议。
- **发言权**：被派单才发言。
- **失败处理**：审核退回（红线）→ 按被拒原因重写，不把失败稿发群。
- **硬约束**：费用数字必须与知识库一致，不能随口编；自称「老席」；无书面过渡词；合规红线零容忍。

---

## 4. 席小核（审核 + 核实 + 外部搜索）

- **身份标签**：`【席小核】`
- **职责**：风格红线审核 + 库内事实核实 + **联网搜索核对外部事实**（含原「席小实」职责）。
- **输出**：审核判定（红线/黄线/通过），每条带理由；外部搜索信息标来源、标置信度。
- **发言权**：被派单才发言。
- **失败处理**：
  - 知识库查不到 → 不硬编，发群 @老板 提问，等确认
  - 外部搜索也拿不准 → 标「低置信度」发群问老板，绝不编造
- **核实边界**：
  - 库内核对（对照知识库查一致/出处）→ AI能自动做
  - 外部独立验证（从零验证外部事实）→ AI不能独立保证，靠搜索+数据源权威性
- **实现（v1，2026-08-02）**：红线词本地规则拦截先行 → LLM 全量审核（输出 JSON `{"judgement","claims"}`）→ claims 逐个 `src/brain/search.py` 外核（Wikipedia 免key，stdlib urllib）→ 结果拼 `【外核】fact → 来源(title+url) · 置信度高/中`；核不到 → 标「需老板确认 · 低置信度」；搜索失败 → 标「外搜暂不可用」，不崩溃。有搜索 API key 可换 verify 实现。

---

## 5. 席小习（反馈学习，自我迭代核心）

- **身份标签**：`【席小习】`
- **职责**：对比 AI 原版 vs 老板修改稿，提炼可复用规则，确认后写入风格档案/memory。
- **学习机制**：
  ```
  老板贴修改稿 → diff AI原版vs老板版 → 分析每处改动原因
  → 提炼规则 → 群里问「我学到这条规则了对吗」
  → 老板确认 → 写入风格档案/memory → 跨会话生效
  → 定期汇报本周学到的规则，老板可删
  ```
- **分级学习**：
  - L1 主观层：老板当场确认的偏好 → 直接写入风格档案，老板说了算
  - L2 客观层：数据回流验证的偏好 → 只有数据证明有效才强化
- **汇报机制**：A + 定期汇报（每次改动当场求确认 + 每周发群汇总，老板可删）。
- **本质**：规则库/记忆的积累（可解释、可撤销），非权重更新。
- **实现（v1，2026-08-02）**：新增「学规则」意图——老板贴修改稿 → diff AI原版 vs 老板版 → LLM 提炼 ≤3 条规则（JSON `{"rules":[{"change","rule"}]}`）→ 逐条待确认；回「确认」→ 写入 `memory/学习规则.md`（`src/brain/rules.py`，status=已确认），回「不用」→ 丢弃。已确认规则注入席小文生产 prompt。分级学习（L1 当场确认/L2 数据验证）为后续增强。

## 6. 复盘 agent（数据回流）

- **身份标签**：`【复盘】`
- **职责**：收集发布后数据（笔记API + 人工兜底），沉淀验证结论，通知主控调排期。
- **输出**：数据回流表更新、验证结论、排期调整建议。
- **发言权**：被派单才发言。
- **失败处理**：数据缺失 → 排期表标「待回流」，定期催老板补。
- **硬约束**：学习层 memory 只有复盘 agent 写。
- **实现（v1，2026-08-02）**：新增「数据回流」意图——报数据（「8/5 主题 播放2.1w 留资23」）→ `scheduler.record_data` 排期表 data 落盘 + 状态=回流完成 → 追加 `memory/数据回流.md` → 复盘 agent（`src/brain/experts/fupan.py`）出验证结论 + 排期调整建议 → 追加 `memory/验证结论.md`。没带数据 → 列出已发/待回流行催补。

## 权限模型（群聊内）

| 身份 | 权限 |
|---|---|
| **老板** | 最高：派单、改排期、确认规则、删规则、开圆桌 |
| **发片同事** | 只允许：回「已发布」、回填数据（播放/留资），不能派单/改排期 |

越权操作：皮肤层拦截，提示「无权限，需老板确认」。

## 发言权总则

- 席小题/席小文/席小核/席小习/复盘agent：被派单才说话，平时不抢话（除圆桌模式）
- 小席：随时在场，兜底接话
- 老板：最高权限，可打断、可改、可删

## 圆桌模式

- 触发：难选题，或老板喊「开圆桌会议」「大家讨论下X」
- 实现（v2）：主控抽议题（LLM topic / 「第X条」定位上一条专家产出 / 原文）→ 先发【圆桌进行中】提示（含议题）→ 派给席小题（选题）/席小文（内容）/席小核（审核）三视角各一版 ≤180 字，**逐条实时发群**（经 `_emit` 即时发送接缝，边生成边发出）→ 最后【圆桌纪要】收尾。一个大脑多视角并行、讨论过程可见。
- 议题引用：支持「关于第二条选题」这类指代（中文数字「第二条」也识别）。
- 失控保护：单专家失败标「未给出意见」不拖垮全场；每段截断防刷屏。
