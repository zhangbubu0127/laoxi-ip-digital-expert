# 老席留学IP数字专家 PRD

## AI 速读卡

- 一句话：一个飞书群，老板丢需求，一群 AI 专家（选题/写作/审核/学习/复盘）在主控调度下协作产出短视频内容，达到曝光、留资、信任三个目标。
- 形态：飞书群聊 = 唯一入口；单 bot（先用一个飞书自建应用）扮演全部专家，靠「【席X】」身份标签区分，后续可迁多 bot。
- 核心角色：主控调度 agent（路由/排期/熔断）+ 席小题（选题调研）+ 席小文（写手）+ 席小核（审核核实+外搜）+ 席小习（反馈学习）+ 复盘 agent（数据回流）。
- 关键机制：**小席规划器**（一次 LLM 调用产出自然回复 + 末尾可选【行动】JSON，模型原生语言理解，取代意图表+关键词兜底链）、泛类内容素材库 + 完整讨论记录（拉群历史）、排期表（模板+数据+老板可覆盖）、圆桌模式（三专家多视角逐步输出：先【圆桌进行中】提示再逐条实时发三视角观点）、写脚本流水线逐步输出、自我迭代飞轮（diff学习）、**市场情报库**（竞对分析/ 竞对图谱+中新教育对比+雷达热点，席小题取材兼顾两侧，别清一色只用单一来源）、熔断（token记账）、权限分级（老板=产品=全权，用户=只读/反馈/追问，发片同事=确认发布）、回复带【席X】身份标签。
- **2026-08-05 新增**：① 群内对话式改表结构（老板/产品「单开一列放脚本内容」→ 多维表格直接加列）；② 定稿→问排期→记录（审核通过后小席主动问排哪天几点，带脚本内容+负责人+来源群入列）；③ 发布前 1 小时提醒 @ 发片同事核对；④ 改排期空参数禁止静默编造（改问老板）；⑤ 风格分库（**已实现 2026-08-05 Part B**）：说话逻辑/风格按用户分库（knowledge/风格/<用户>/创作要求.md），配置多个风格库时出脚本前小席先问「按谁的风格写」，答后记 `_last_style[chat]` 复用，可「按XX的风格写」直接点名；学习规则按用户分库（memory/学习规则-<用户>.md）不污染。
- **2026-08-07 新增**：① 小席规划器——路由从「19 类意图表 + 关键词兜底链」改为一次 LLM 调用产出（自然回复, 可选动作），模型原生语言理解为主，知识库当参考不当考试答案；② 专家 prompt 去约束化——席小题/席小文/席小核只保留承重锚点（脚本头/审核三态/选题序号），结构按主题自然组织；③ 新动作「改审核看法」——老板纠正席小核判断/给审核标准 → 席小习提炼 → 直接落已确认规则，下次审核自动对齐；④ 规则类型化——每条规则标 type（表达偏好/事实规则/内容策略/禁止事项），防「一条例子被学成绝对真理」；⑤ 审核理由双层门——仅当席小核刚邀约过「需要给您展示理由吗？」且短回应含理由词才直发审核详情，长消息不误触发旧存档。
- **2026-08-08 新增**：确认已发布/数据回流自然语言化——执行器优先吃 planner 结构化 params（date/topic/data），正则兜底增强（剥《》「」按标题模糊匹配排期行、无日期按最近「已发」行回落、数据指标正则提取浏览/播放/点赞/评论/收藏/转发/留资），「《标题》已发布 + 数据」一条消息连动标已发+回流；planner params 契约扩 data；**跨消息暂存**——报数据时没有可落账的「已发」行 → 暂存待回流数据，等确认「已发布」自动补回流（v1.7）；修 mark_published 只认「待发」导致真实「待产」行标不了已发的 bug。
- **2026-08-09 新增**：**排期意图修复 + 意图识别防误判**——① 排期意图兜底：老板「排 8/8 18:15 负责人张艺宝」→ 认排期意图（日期/时间/负责人/「排」字）用刚定稿选题排期、负责人解析，无明确数量绝不编占位行（修 8/8 生产事故 3 条「曝光选题N」垃圾占位）；② 查「选中的/刚定稿」选题 → 优先回刚定稿那条（修答非所问）；③ 标已发日期笔误容忍：日期对不上但标题唯一命中 → 按表里日期标已发并注明；④ 意图防误判：看排期表硬锚（「看/查/打开+表格词」→ 不依赖 LLM 直接给链接）+ 确认已发布防呆（原文无「已发布/发了」等确认词 → 不标已发，回「标哪条？说日期+标题」）。
- 部署：本机 lark-cli 先跑通，解耦皮肤层/大脑层，为迁多 bot 铺路。

## 第一章：产品概述

### 1.1 背景与问题

老席是新加坡留学赛道 IP（13年行业老兵、北方口语、反常识劝退钩子）。当前内容生产的三个目标**全部未达成**：大曝光（流量起不来）、留资（有量没转化）、信任（咨询不成单）。现有生产靠人肉，慢且不稳定，且没有系统性的排期和复盘机制。

### 1.2 产品目标

通过「群聊多专家协作」形态，把内容生产从「人肉散打」升级为「系统作战」：
- **曝光**：选题调研驱动，踩热点、反常识钩子，提高被算法选中概率。
- **留资**：内容按目标分类（曝光/留资/信任）排期，留资内容带明确 CTA。
- **信任**：审核红线把关 + 人工发布确认 + 数据回流验证，建立可信循环。

### 1.3 可行性边界

- **本产品不解决发布**：智能体不能发片，发片是人工动作，发布后同事回群确认。
- **不解决投放执行**：投流/矩阵是真人运营的活，AI 只给决策支持（排期建议）。
- **不保证外部事实绝对正确**：AI 靠知识库 + 外搜，最终权威在知识库维护。
- **「AI 学习」是规则/记忆积累**，可解释、可撤销，非权重更新。

## 第二章：整体布局与导航

### 2.1 产品形态

飞书群聊。无独立 App、无网页端（本机阶段）。老板的全部操作都发生在群里，通过自然语言完成。

### 2.2 群聊消息视图（老板视角）

```
─────────────────────────────────────
 飞书群 · 老席留学数字专家
─────────────────────────────────────
 老板：帮我出3个没拍过的选题，信息差角度
 【席小题】基于本周调研，推荐3个：
          1. 预算不够？这条路线最省（留资向）
          2. 别去新加坡？那去哪（曝光向）
          3. 老席13年为什么不涨价（信任向）
 老板：第1个写条脚本，60秒
 【主控调度】流程：席小题选题已确认 → 席小文写作 → 席小核审核
 【席小文】脚本 v1 已出：…
 【席小核】审核通过，无红线，1条黄线建议改
 【主控调度】全流程完成。要发布版还是改？
─────────────────────────────────────
```

### 2.3 导航规则

| 老板意图 | 入口 | 系统响应 |
|---|---|---|
| 出选题 | 说「出选题」或 @席小题 | 派单席小题 |
| 写脚本 | 说「写脚本关于XX」 | 流水线逐步输出：主控提示 → 席小文出稿 → 席小核审核 |
| 看排期 | 说「看排期表」 | 贴当前排期表 |
| 改排期 | 说「下周三要3条曝光」 | 改排期表标记老板指定 |
| 改排期（确认选题） | 说「这条选题通过了，把类型和选题都上传」/「那可以排期发布了」 | 追溯刚定稿脚本的真实选题+类型（曝光/留资/信任）同步排期表+多维表格，不生成占位 |
| 圆桌讨论 | 说「大家讨论下XX」/「开圆桌会议」 | 主控抽议题 → 【圆桌进行中】提示 → 逐条实时发席小题/席小文/席小核三视角 → 【圆桌纪要】收尾 |
| 反馈修改 | 说「这个脚本不行」+ 贴改稿 | 从会话记忆找最近一条专家产出，路由给产出者改写 |
| 连续性指代 | 说「第1个写条脚本」/「这个脚本不行」/「为什么选这个角度」 | 带 7 轮上下文识别意图，路由给对应专家 |
| 记素材 | 说「记素材：<泛类内容>」 | 存入素材库 workspace/素材/ |
| 更新市场情报 | 说「更新情报/搜竞对/现在什么话题热」 | 实时搜热点+竞对线索（尽力而为），刷新竞对分析/热点话题.md + 竞对线索.md |
| 看完整讨论 | 说「看完整讨论」 | 拉最近群历史并展示 |
| 确认已发 | 发片同事说「8/3已发布」 | 排期表状态标已发 |

## 第三章：核心模块详细设计

### 模块 A：主控调度 agent

**职责**：群聊主控（小席规划器：一次 LLM 调用产出自然回复 + 可选【行动】动作，带 7 轮会话记忆；模型判断「真需要系统落地动作」才写动作，纯聊天/给意见不写；**v1.8 意图防误判**：看排期表硬锚先于规划器（`_view_schedule_requested` 关键词规则直接给链接），确认已发布防呆（`_has_publish_confirm` 原文须含确认词））、动作执行（动作名→既有执行器分发表；**v1.6 执行器优先吃 params 结构化 date/topic/data，确认已发布/数据回流兜底自然语言解析；v1.7 报数据无已发行 → 暂存待回流数据，等确认已发布自动补回流；v1.8 标已发日期笔误容忍**）、素材库（记素材/读素材）、完整讨论（拉群历史）、排期管理（**v1.8 排期意图兜底刚定稿选题**）、熔断、token 记账、知识检索。

**状态流转**：
```
收到消息 → 识别身份（老板/产品/发片同事/用户）→ 权限拦截 → 读会话记忆(7轮) → 看排期表硬锚拦截（v1.8：含「看/查/打开+表格词」直接给链接，不进规划器）→ 小席规划器（一次 LLM 调用产出自然回复 + 可选【行动】JSON）
  ├─ 无【行动】（纯聊天/给意见）→ 用规划器自然回复
  ├─ 动作=确认已发布但原文无「已发布/发了」等确认词（v1.8 防呆）→ 不执行标已发，回「标哪条？说日期+标题」+排期表链接
  ├─ 动作（出选题/写脚本/审核脚本/改审核看法/学规则/记素材/改排期/更新市场情报/查记录/圆桌讨论/追问/要审核理由/确认已发布/确认排期/改表格结构…）→ 动作名查分发表，命中执行、非法名按无动作（动作命中丢弃规划器自然回复，执行器消息唯一，防双发）
  ├─ 上下文关联（第1个/这个脚本/为什么选这个）→ 从会话记忆消解指代后派单
  ├─ 反馈修改 → 找最近一条专家产出，路由给产出者改写
  ├─ 排期指令 → 改排期表 → 回显（空参数无明确信息 → 问老板细节，不编占位行）
  ├─ 改表格结构（单开一列/加个字段）→ 多维表格加列（仅老板/产品）
  ├─ 写脚本审核通过 → wait_schedule：小席问排期 → 老板给日期时间 → 记录排期（带脚本内容+负责人+来源群）
  └─ 任何流水线态活跃（wait_wen/wait_he/wait_fix/wait_boss/…）→ 强制 action=None，防规划器中途乱派单
→ 专家产出即时发回群（写脚本/圆桌逐步输出）→ 本轮写入会话记忆 → 记 token → 熔断检查
→ 常驻后台：每 30s 检查发布前 1 小时提醒 → 命中则 @ 负责人核对
```

**失败路径**：
1. 规划器输出无法解析 / 动作名非法 → 按无动作处理，用自然回复聊天，不进聊天兜底乱发；只有规划器崩溃（异常）才落 `by_keyword` 关键词兜底（高信号指令不静默）。
2. 专家调用超时 → 重试1次，仍失败回群明说。
3. token 接近熔断阈值 → 提前报告，建议暂停/降配。
4. 反馈修改/追问无上一条产出 → 回「没有找到可修改/可追问的上一条产出」。

**硬约束**：主控是唯一调度者；专家被派单才说话（除圆桌）；排期表唯一写权限在主控。

### 模块 B：席小题（选题 + 调研合体）

**职责**：基于知识库 + 市场调研（热点/竞品/家长痛点），产出选题。调研是选题的组成部分，不单设调研角色。

**市场情报库（2026-08-05 落地）**：`knowledge/竞对分析/` 三个来源——① 竞对图谱.md（竞对劣势当选题钩子）+ 中新教育对比.md（人工润色）；② 热点话题.md（雷达 `scripts/sync_radar.py` 机器覆盖，每日热点）；③ 竞对线索.md（「更新市场情报」意图 `market.refresh()` 原样存线索）。席小题 `_system()` 注入【竞对情报/市场热点】段，出选题取材「尽量兼顾两侧」——别清一色只用一个来源（市场情报段 / 本地知识库），每条依据标注取材来源（市场热点/竞对/知识库）。（v1.5 去约束化：由「必须一半对一半」硬配额改为引导性表述，选题少时允许单侧取材）

**输出**：选题清单，每条标注类型（曝光/留资/信任）、调研依据、角度。

**状态流转**：接单 → 拉调研（热点+竞品+知识库）→ 出选题清单 → 回群。

**失败路径**：
1. 调研源不可用 → 用知识库兜底，标注「调研降级」。
2. 选题被老板否 → 记录否因，下次避开同方向。

**硬约束**：选题必须带类型标签（排期依赖）；选题角度须有调研或知识库依据，不空想。

### 模块 C：席小文（写手，内嵌风格）

**职责**：基于选题 + 知识库 + 风格档案产出多版文案。含原「席小风」的风格打磨职责（风格是写作约束，不是独立环节）。

**输出**：脚本 v1/v2…，附结构拆解、封面文字、钩子词、投放建议。（v1.5 去约束化：六大模块由「必须严格逐段照抄」改为「参考结构，按主题自然组织，允许调整段落」，唯一硬锚点是第一行 `## 脚本 vX：标题`；费用数据从「唯一事实来源」改为「事实参考，写作时核对」）

**状态流转**：接选题 → 匹配知识域 → 选钩子模板 → **按当前风格用户写作**（knowledge/风格/<用户>/创作要求.md，默认老席；主控派单任务带【风格:用户名】标记切换）→ 自检 → 出稿。

**失败路径**：审核退回（红线）→ 按被拒原因重写，不把失败稿发群。

**硬约束**：费用数字必须与知识库一致，不能随口编；自称「老席」（非老席风格用户时以该用户人设为准）；无书面过渡词；合规红线零容忍。

### 模块 D：席小核（审核 + 核实 + 外部搜索）

**职责**：风格红线审核 + 库内事实核实 + **联网搜索核对外部事实**。含原「席小实」的核实职责。

**审核输出**：红线/黄线/通过判定，每条带理由；外部搜索信息标来源、标置信度。

**状态流转**：接脚本 → 库内核对 → 外搜核对 → 出判定 → 通过发主控 / 退回小文。

**失败路径**：
1. 知识库查不到 → 不硬编，发群 @老板 提问。
2. 外搜也拿不准 → 标「低置信度」发群问老板，绝不编造。

**硬约束**：任何不确定事实必须走「问老板」，禁止静默编造。

### 模块 E：席小习（反馈学习，自我迭代核心）

**职责**：对比 AI 原版 vs 老板修改稿，提炼可复用规则（每条带 type：表达偏好/事实规则/内容策略/禁止事项），确认后写入风格档案/memory。

**输出**：提炼的规则 + 给老板的确认询问 + 定期（每周）学习汇报。

**状态流转**：
```
老板贴修改稿 → diff AI原版vs老板版 → 分析每处改动原因
→ 提炼规则 → 群里问「我学到这条规则了对吗」
→ 老板确认 → 写入对应风格用户的档案/memory → 跨会话生效
→ 定期汇报本周学到的规则，老板可删
```
（2026-08-05 Part B：规则按风格用户分库——老席 memory/学习规则.md，其余 memory/学习规则-<用户>.md；学习路由按该聊天最近所用风格）

（2026-08-07 改审核看法：老板纠正席小核判断/给审核标准（如「这句可以说」「金额别太严谨」）→ 小席规划器命中「改审核看法」动作 → 席小习提炼 → **直接落已确认规则**（老板已拍板，跳过待确认），席小核 prompt 注入规则后下次审核自动对齐。老板答复 wait_boss 审核疑问拍板时同样落规则，固定标「事实规则」。）

**失败路径**：老板不同意提炼的规则 → 丢弃该规则，记录「被否规则」。

**硬约束**：每次学习当场求确认（A方案）；L1主观层老板说了算，L2客观层需数据验证才强化。

### 模块 F：复盘 agent（数据回流，飞轮闭环）

**职责**：收集发布后数据（笔记API + 人工兜底），沉淀验证结论，通知主控调排期。

**输出**：数据回流表更新、验证结论、排期调整建议。

**状态流转**：排期表有「已发」→ 等数据（API/人工）→ 分析 → 写 memory/验证结论 → 通知主控调后续排期。

**自然语言录入（v1.6→v1.7）**：老板用自然语言报数据（无 M/D 日期、无「日期 选题 数据」标准格式）也能入账——执行器优先吃 planner params，兜底正则提取「浏览/播放/点赞/评论/收藏/转发/留资 + 数字」指标、无日期按最近一条「已发」行回落存档；「《标题》已发布 + 数据」一条消息连动标已发+回流；**跨消息（v1.7）**：报数据时没有可落账的「已发」行 → 数据暂存（7200s TTL），等之后确认「已发布」自动补回流；带日期/标题的暂存只在匹配刚标已发的行时应用，防数据串台。

**失败路径**：
1. 数据缺失 → 排期表标「待回流」，定期催老板补。
2. API 拿不到 → 人工兜底录入。

**硬约束**：学习层 memory 只有复盘 agent 写；数据缺失必须显式标注，不猜测。

### 模块 G：排期表

**形态**：本机用本地 Markdown 表（源真），写后镜像到飞书多维表格（老板看板）。主控唯一写权限。

**结构（10 列）**：`日期 | 发布时间 | 内容类型 | 选题 | 目标 | 状态 | 负责人 | 数据回流 | 脚本内容 | 来源群`
- **脚本内容**：定稿脚本压成单行入列，同步多维表格。
- **来源群**：排期创建时记录的所在群，仅本地（不同步），供发布提醒定位群。

**状态机**：`待产 → 审核中 → 待发 → 已发（人工确认）→ 回流完成`

**关键行为（2026-08-05）**：
- **定稿 → 问排期 → 记录**：写脚本审核通过后，小席当场问「要不要上排期表？排哪天几点？负责人是哪个发片同事？」；老板回「排 8/10 12:00」→ 入列（带脚本内容+负责人+来源群）；回「先不排」→ 不记；超时安静撤等待态。
- **群内加列**：老板/产品说「单开一列放脚本内容/加个字段」→ 意图「改表格结构」→ `lark-cli +field-create` 直接给多维表格加列。脚本内容列已接入本地 schema 自动填；负责人列已在；白名单外列创建但需手动维护。
- **发布前 1 小时提醒**：每 30s 检查排期表，命中「今天 + 距发布 ≤60 分钟 + 待产/待发 + 有来源群」→ 往来源群提醒并 @ 负责人（发片同事）。
- **禁止静默编造**：改排期 params 空且无明确排期信息 → 问老板细节，绝不生成占位行。
- **排期意图兜底刚定稿选题（2026-08-09）**：老板「排 8/8 18:15 负责人张艺宝」→ 认排期意图（`_has_schedule_intent`：日期/时间/负责人/「排」字/params.date）→ 用刚定稿选题（`_last_passed`）落行，负责人 `_parse_owner` 解析；**无明确数量或选题 → 回「排哪条选题/排几条」，绝不编「曝光选题N」占位行**（修 8/8 事故 3 条垃圾占位）。

**硬约束**：已发状态必须人工确认（智能体不能发片）；老板/产品可覆盖任何排期。

**已发确认（v1.6→v1.8）**：老板/发片同事说「《标题》已发布」「8/3已发布」→ 剥《》「」按标题模糊匹配标「已发」，无日期也认；带数据一条消息直接连动回流；匹配范围 v1.7 放宽为 待产/待发 双状态（真实排期行停留「待产」，此前只认「待发」会标不了）。**v1.8 日期笔误容忍**：日期对不上但标题在待发行唯一命中 → 按表里日期标已发，回执注明「你报的日期 X 表里是 Y，已按 Y 确认」；撞题歧义（多条同标题候选）不猜，报「未找到对应待发条目」。**v1.8 防呆**：原文无「已发布/发了」等确认词（如「看一下表格」被误判）→ 不标已发，回「标哪条？说日期+标题」+排期表链接。已发状态始终人工确认，系统不自动发片。确认后若有暂存的待回流数据且匹配该行 → 自动补回流。

### 模块 H：素材库 + 完整讨论

**素材库**：用户投喂的泛类内容（热点文章/竞品爆款/灵感）存 `workspace/素材/`。老板说「记素材：<内容>」→ 主控存成带时间戳的素材文件；席小题出选题时把最近 5 个素材并入 prompt，结合知识库出题。

**完整讨论**：皮肤层经 lark-cli `+chat-messages-list` 拉取最近群历史（只留真人文本发言），注入大脑层接缝。出选题时并入席小题上下文；老板说「看完整讨论」→ 拉取并展示。

**状态流转**：
```
老板贴内容 +「记素材」→ 皮肤层存 workspace/素材/（来源/时间/原文）
出选题 → 席小题读 知识库 + 素材库(最近5个) + 最近群讨论 → 出题
```

**失败路径**：拉群历史失败/未接入 → 出选题照常（只用素材库+会话），「看完整讨论」回「拉取未接入或暂无」。

**硬约束**：素材与知识库冲突时以知识库事实为准（席小题铁律）；素材库只做追加，v1 不做修改/删除。

## 第六章：技术架构

### 6.1 分层（解耦，核心）

- **皮肤层**：飞书 bot（lark-cli）。收发消息、识别 sender、权限拦截。
- **大脑层**：专家逻辑（选题/写作/审核/学习/复盘），不依赖 bot 形态。
- **管道**：皮肤↔大脑之间约定接口，传消息内容 + 身份信息。
- **存储层**：knowledge/（事实层只读）、workspace/（工作层）、memory/（学习层）。

### 6.2 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 消息收发 | lark-cli（im.message.receive_v1 事件 / messages-send） | 已装已登录，验证过 |
| 事件消费 | lark-cli event consume | 常驻监听群消息 |
| 专家执行 | DeepSeek API（模型 deepseek-v4-flash） | 知识库驱动 prompt；key 走 gitignored secrets |
| 知识存储 | 本地 Markdown 文件 | 先文件后多维表格 |
| 外搜核对 | 已实现 v1：Wikipedia API 免key（stdlib urllib），核不到标「需老板确认 · 低置信度」；有搜索 API key 可换 | 席小核用 |
| 数据回流 | 笔记API（已做过）+ 人工兜底 | 搭完验证替代性 |

### 6.3 可替换与不可变

- **不可变（硬约束）**：皮肤/大脑解耦；已发人工确认；异常走问老板；知识库只读；排期表主控独写。
- **可替换**：bot 数量（单→多）、排期表存储（文件→多维表格）、数据源（API→人工）、专家数量。

## 第七章：交互细节

### 7.1 触发形态（同时存在）

1. 显式：@席X + 需求 → 定向派单。
2. 隐式：说「写脚本/出选题/审核」→ 小席规划器（一次 LLM 调用产出自然回复 + 可选【行动】JSON，带 7 轮会话记忆，模型原生语言理解）。
3. 上下文关联：说「第1个」「这个脚本」「为什么选这个」→ 消解指代后路由（反馈修改/追问找最近一条专家产出）。
4. 定向：说专家名字 → 只派该专家。
5. 素材投喂：贴泛类内容 +「记素材」→ 入素材库；出选题时自动读素材库 + 最近群讨论。
6. 默认：规划器判定纯聊天/无落地动作 → 用规划器自然回复继续对话（v1.5 起不再回死板的「需要我做什么？」清单）。

### 7.2 发言权

- 专家：被派单才说话（除圆桌）。
- 主控：随时在场兜底。
- 老板：最高权限，可打断、可改、可删。
- 发片同事：只可回「已发布」、回填数据，越权被皮肤层拦截。

### 7.3 圆桌模式

- 触发：难选题，或老板喊「开圆桌会议」「大家讨论下X」。
- 表现（v2）：主控抽议题（LLM topic / 「第X条」定位上一条专家产出 / 原文）→ 先发【圆桌进行中】提示（含议题）→ 派给席小题（选题）/席小文（内容）/席小核（审核）三视角，各出一版 ≤180 字观点，**逐条实时发群**（边生成边发出，讨论过程可见）→ 最后主控发【圆桌纪要】收尾。
- 议题引用：支持「关于第二条选题」这类指代（中文数字也识别）。
- 失控保护：单专家失败标「未给出意见」不拖垮全场；每段截断防刷屏。

### 7.4 排期表操作

- 看：老板说「看排期表/看一下表格/排期表链接」→ 硬锚直接贴表/给链接（v1.8，不依赖规划器）。
- 改：老板说「下周三要3条曝光」→ 主控改表标 bossOverride；「排 8/8 18:15 负责人张艺宝」→ 排期意图兜底刚定稿选题（v1.8），无明确数量绝不编占位。
- 确认已发：发片同事说「8/3已发布」→ 状态待发→已发（v1.8：日期笔误但标题唯一命中 → 按表里日期标并注明；原文无确认词 → 防呆不标，回「标哪条？」）。

## 第十一章：开发者交接说明

### a) 先建什么
先建 P0 闭环：皮肤层（lark-cli 收/发消息）+ 大脑层主控调度 + 排期表文件 + 席小题/席小文/席小核 基础流水线。跑通「老板说写脚本 → 出稿 → 审核 → 回群」即第一个里程碑。

### b) 不要改什么（硬约束）
- 皮肤/大脑解耦，迁移多 bot 只换皮肤层。
- 已发状态必须人工确认，智能体不能自动标已发。
- 任何不确定事实走「问老板」，禁止静默编造（含改排期空参数：绝不生成占位行）。
- 知识库事实层只读；排期表主控唯一写权限；memory 学习层复盘 agent 独写。
- 加列（改表格结构）仅老板/产品；用户只读（看排期表/反馈/追问），写脚本/改排期/加列一律拦截。

### c) 可以自由发挥的地方
- 专家数量、角色命名、排期模板节奏、圆桌触发条件、数据回流源（API 或人工的替换方式）。

### d) 已知的未知项
- 笔记API 能否替代人工数据回流 —— 待系统搭完验证。
- 老板和发片同事的飞书 open_id —— 拉群后获取并绑定角色；`publisher_open_ids` 未登记时发布提醒只能文本点名不能真 @。
- 用户角色登记 —— 后续入群用户由老板告知谁老板级/谁用户级，登记 `config/roles.json` 的 `user_open_ids`（gitignore）。
- 飞书自建应用凭证 —— 本机阶段创建 1 个；迁多 bot 再建更多。
- 排期模板的默认节奏数字 —— 需用真实数据校准。
- 提醒去重是进程内存 —— 小席重启会重置，最多重复提醒一次；要跨重启去重需落盘（暂不做）。

### e) 验收剧本
1. 在飞书群说「帮我出3个选题」→ 收到席小题选题清单，各带类型标签。
2. 说「第1个写脚本60秒」→ 收到席小文脚本 v1 + 席小核审核结论。
