## 1. 项目定位

群聊里多个专家协助老板（老席）的内容生产，达到**大曝光、留资、获得信任**三个目标。
通过飞书群接入，多智能体协作，小席agent统一编排。

## 2. 目标现状

曝光、留资、信任**三个都没有**，全部要建，三引擎并行。不是选一个。

## 3. 边界（从0定义）

- **架构从0重建**：不沿用旧skill/旧agent。
- **业务资产保留当原料**：老席人设、家长原话、爆款规律、合规红线、费用数据等市场验证过的内容继续使用。
- 老资料（laoxi skill、老席审核agent、knowledge结构）只参考，不作为架构蓝本。

### 4.1 分层原则（解耦）

- **皮肤层**（飞书bot）：只负责收发消息、识别发送者身份、权限拦截。
- **大脑层**（专家逻辑）：选题/写作/审核/学习/复盘，完全不依赖是哪个bot。
- **会话记忆**：大脑层按 `chat_id` 保存最近 7 轮对话（LRU），小席规划器与专家派单都读它，实现「第1个」「这个脚本」等跨轮指代。
- **小席规划器（v1.5）**：主控不再背 19 类意图表 + 关键词兜底链。一次 LLM 调用同时产出（自然回复, 可选动作），末尾 `【行动】{"action":"<白名单>","task":"<规范任务>","params":{}}` 单行 JSON 才是系统落地契约；只有真需要系统执行才写动作。非法/未知动作名 → 按无动作处理，不进聊天兜底乱发。任何 `_pipelines` 流水线态活跃时强制 `action=None`（防自动改稿循环重复派活）。`intent.py` 的 `by_keyword` 仅作 LLM 崩溃兜底（`_fallback_planner` try/except 包住）。
- **素材库**：用户投喂的泛类内容存 `workspace/素材/`（工作层），记素材入库，席小题出选题时读入。
- **完整讨论**：皮肤层经 lark-cli `+chat-messages-list` 拉取群历史，注入大脑层接缝 `_pull_history`，出选题/「看完整讨论」时使用。
- **圆桌讨论**：主控多视角并行逐步输出——先发【圆桌进行中】提示，再把议题派给席小题/席小文/席小核各出一版观点逐条实时发群，最后主控发【圆桌纪要】收尾。
- 两层通过**约定管道**传话（消息内容 + 身份信息）。
- **真多bot（已落地）**：6 个角色 = 6 个独立飞书应用（小席/席小题/席小文/席小核/席小习/席小盘）。主控 @派单（`<at user_id>`），专家 bot 被 @ 自触发；信息共享走「@消息携带的上下文」+ 共享只读知识库 `knowledge/`；写权限不变（排期表主控唯一、`memory/学习规则.md` 席小习写、`memory/数据回流.md`+`验证结论.md` 席小盘写）。
- **双模式兜底**：`_dispatch_expert` 在未配置 `config/bots.json` 时进程内直接跑专家（单bot/测试环境），配置后走 @ 异步派单——旧行为不回归。

## 5. 智能体组

| 角色 | 职责 | 备注 |
|---|---|---|
| **小席agent** | 收消息→判断触发→派单→汇总→发回；**小席规划器（v1.5）**：一次 LLM 调用产出（自然回复, 可选【行动】动作），带会话历史/团队能力清单/当前流水线/最近席小核审核详情；会话记忆（7轮）；管排期表/熔断/token记账/知识检索 | 顶层，升级自原「管家」；动作级权限（`_PERMISSION_ADMIN`/`_PERMISSION_USER_READONLY`/`_THIRD_BUCKET`）替代意图级 `_ADMIN_ONLY` |
| **席小题** | 选题 + 调研合体 | 不单设席小材；**市场情报能力（2026-08-05）**：`_system()` 注入【竞对情报/市场热点】段（竞对图谱 + 中新教育对比 + 雷达热点话题 + 竞对线索），出选题取材配额引导性（v1.5 去约束化：尽量兼顾市场情报与本地知识库，别清一色单来源，不再「必须各出一半」），每条依据标注取材来源（市场热点/竞对/知识库） |
| **席小文** | 写手，内嵌风格 | 含席小风；脚本输出参考六段式结构（首行固定 `## 脚本 vX：标题`，口播正文 + 结构拆解 + 封面文字 + 钩子词 + 投放建议按主题自然组织，允许调整段落，不强制逐段照抄），修改递增版本号；**按风格库写作（2026-08-05 Part B）**：出脚本读 knowledge/风格/<用户>/创作要求.md（默认老席，缺省回落 人设/老席创作要求会纪要.md）+ 该用户已确认规则；风格由主控派单任务携带【风格:用户名】标记，非老席时切换 |
| **席小核** | 审核 + 核实 + 外部搜索核对 | 含席小实；红线本地拦截（REDLINES 安全层不动）→ LLM 全量审核 → Wikipedia 免key外核 → 核不到标「需老板确认 · 低置信度」；**双段输出协议**：公开段只给【审核结论】（通过/不通过/需老板确认三选一）+ 疑问段（大白话 1-3 条）+ 「需要给您展示理由吗？」，详情段（`===审核详情===` 之后，中文白话逐条理由 + 外核结果，剥 JSON）存后台存档，老板要理由才展示（v1.5 双层门：仅当最近席小核产出带邀约锚点 **且** 短消息含理由词才直发，长消息不再误触发）；**三态判定**：通过/不通过/需老板确认，主控绝不扫「红线」字面，只有明确拒稿信号（不通过/未通过/❌/需改）才 @席小文 改正（最多 2 轮） |
| **席小习** | 反馈学习：diff→规则提炼→确认→写入 | 新增，自我迭代核心；已实现 v1：学规则/确认规则 → memory/学习规则.md，已确认规则注入席小题/席小文/席小核 prompt（**v1.5 按 type 分组注入**：禁止事项/事实规则/内容策略/表达偏好，越靠前越硬守）；**改审核看法（v1.5）**：老板纠正席小核判断/给审核标准 → 席小习提炼 → 直接落已确认规则，下次审核自动对齐；**按用户分库（2026-08-05 Part B）**：学习规则写进该用户学习规则库 memory/学习规则-<用户>.md（老席沿用 memory/学习规则.md），主控确认/席小文引用按聊天最近风格读对应库，不污染他人风格 |
| **席小盘** | 数据回流→排期调整→知识库更新 | 新增，数据飞轮；已实现 v1：报数据 → 排期表 data 落盘 + memory/数据回流.md → 验证结论 + 排期调整建议 → 主控回喂席小题/席小文 |

**多bot形态**：6 角色各自独立飞书应用（`config/bots.json` 注册 profile+open_id）。主控 @派单，专家自触发，上下文随 @ 携带，知识库共享只读。

**核实边界**：
- 库内核对：对照知识库查一致/出处 → AI能自动做
- 外部独立验证：从零验证外部事实 → AI不能独立保证，靠搜索+数据源权威性，责任在知识库维护

- 排期表小席agent唯一拥有写权限

## 7. 角色触发规则

### 7.1 小席路由表

> v1.5 起：路由由「意图表 + 关键词兜底链」改为**小席规划器**——一次 LLM 调用判断要不要系统落地动作（`【行动】{"action":...}`）。下表是常见话术对应的落地动作，具体判定交给模型语言理解，不靠词表硬匹配；`by_keyword` 仅作 LLM 崩溃兜底。

| 老板在群里说 | 主控做什么 |
|---|---|
| 「帮我出个选题」 | 派单给席小题 |
| 「写条脚本，关于XX」 | 走流水线：席小文→席小核；脚本经上下文传给席小核（不刷屏）；席小核只发公开结论（通过/不通过/需老板确认）+ 疑问 + 问理由，详情存后台；判「不通过」→ 主控 @席小文 改正 → 复审，最多 2 轮；老板回短「要/看下」（且席小核刚邀约过「需要给您展示理由吗？」）→ 直发存档的审核详情（v1.5 双层门，长消息不误触发） |
| 老板纠正席小核看法（「这个是可以说的，要修改席小核的看法」「金额别太严谨」「就要说的绝对」） | 动作=改审核看法：@席小习 把老板的话提炼成审核标准 → 直接落已确认规则（老板已拍板，跳过待确认）→ 席小核下次审核自动对齐；可选对最近脚本复审 |
| （配置了多个风格库时）「写条脚本」 | 先问风格：主控「这次按谁的风格写？当前：老席/张艺宝」，答人名 → 记 `_last_style[chat]`（此后该聊天复用）→ 按该风格派单；「按XX的风格写」指令可免反问直接点名 |
| 「看下排期表」 | 贴出当前排期表 |
| 「下周三前要3条曝光内容」 | 改排期表，标记任务 |
| 「这条选题通过了，把类型和选题都上传」/「那可以排期发布了」 | 改排期表：追溯刚定稿脚本的真实选题+类型（曝光/留资/信任）同步排期表+多维表格，不生成占位 |
| 「单开一列放脚本内容」/「加个字段」 | 改表格结构：给多维表格加列（`+field-create`），仅老板/产品。脚本内容列已接入本地 schema 自动填；负责人列已在；白名单外列创建但需手动维护 |
| （写脚本审核通过后）小席：「要不要上排期表？排哪天几点？」老板：「排 8/10 12:00」/「先不排」 | 定稿→问排期→记录：wait_schedule 状态，老板给日期时间→写排期行（脚本内容+负责人+来源群），回「先不排」→ 不记 |
| 「大家讨论下XX」/「开圆桌会议」 | 触发圆桌模式：主控先发【圆桌进行中】提示，@席小题/席小文/席小核三视角观点，最后【圆桌纪要】收尾 |
| 「这个脚本不行」 | 反馈修改（修改飞轮）：路由给产出者改写 **且** @席小习 diff 学差异 → 提炼规则待老板确认 |
| 「为什么选这个角度」 | 追问：从会话记忆找最近一条专家产出，路由给产出者讲依据 |
| 「第1个写条脚本」 | 上下文关联：读会话记忆上轮选题，@席小文写第1条 → **主控主动 @席小核 审核** |
| 「记素材：<内容>」 | 存进素材库 workspace/素材/ |
| 「更新情报/搜竞对/现在什么话题热」 | 更新市场情报：`market.refresh()` 实时搜热点+竞对线索（尽力而为，风控时回落情报库）→ 写竞对分析/热点话题.md + 竞对线索.md，回执条数 |
| 「看完整讨论」 | 皮肤层拉最近群历史并展示 |
| 「席小题，换选题方向」 | 名字关键词定向，只派席小题 |
| 「8/3普娃逆袭 播放2.1w 留资23」 | 数据回流（数据飞轮）：主控存档排期表 → @席小盘 存档+分析+排期建议 → **主控 @席小题/@席小文 喂效果反馈** |

### 7.2 触发形态（同时存在，不互斥）

1. 显式命令：@agent名 + 需求 → 直接派单
2. 隐式意图：说"写脚本/出选题/审核"（不@）→ **小席规划器** LLM 判定要不要落地动作（写【行动】JSON）；纯闲聊/给意见/纠看法不写动作，只自然回复
3. 上下文关联：说「第1个」「这个脚本」「为什么选这个」→ 带 7 轮会话记忆消解指代后路由
4. 默认状态：没触发关键词 → 主控回「需要我做什么？出选题/写脚本/看排期/讨论？」
5. 定向指挥：说专家名字 → 主控只派给该专家（等效软@）
6. 素材投喂：贴泛类内容 +「记素材」→ 入素材库；出选题时自动读素材库 + 最近群讨论
7. 圆桌讨论：说「开圆桌会议/大家讨论下X」→ 圆桌意图 → 主控逐步输出三视角

### 7.3 发言权边界

- 席小题/席小文/席小核/席小习/席小盘：**只响应主控 @ 派单**（自触发），平时不抢话（除圆桌模式）；老板/产品直接 @ 不响应，由主控带上下文重新派单，避免双响应。
- 小席：随时在场，兜底接话；专家 bot 输出经 `handle_bot_output` 推进流水线。
- 老板：最高权限，可打断、可改、可删。

## 8. 圆桌模式

- 触发：难选题，或老板喊「开圆桌会议」「大家讨论下X」。
- 实现（v2 已落地）：主控先发【圆桌进行中】提示（含议题），随后席小题（选题视角）/席小文（内容视角）/席小核（审核视角）各出一版 ≤180 字观点，**逐条实时发群**（经 `_emit` 即时发送接缝，不等全部生成完），最后主控发【圆桌纪要】收尾。一个大脑多视角并行、边出边发，讨论过程可见。
- 议题来源（`_roundtable_subject`）：① LLM 抽取的 topic 参数 → ② 内容里「第X条/第X个」定位上一条专家产出中的对应条目（支持中文数字「第二条」）→ ③ 上一条专家产出首行 → ④ 原文清洗后。无议题则回引导，不空转。
- 失控保护：单专家失败标记「未给出意见」不拖垮全场；每段观点 ≤180 字截断防刷屏。
- 发言权：圆桌属被派单形态，专家平时仍不抢话。

## 9. 排期表

小席唯一写权限。本地 `workspace/产出/排期表.md` 为源真（**10 字段**），写后镜像到飞书多维表格「老席排期表」（皮肤层 `skin/base_bridge.sync_rows` 经 `scheduler.set_base_sync` 注入；无 Base 配置时静默跳过，单 bot/测试兜底）。改排期回执附多维表格链接。

```
| 日期 | 发布时间 | 内容类型 | 选题 | 目标 | 状态 | 负责人 | 数据回流 | 脚本内容 | 来源群 |
|------|---------|---------|------|------|------|--------|---------|---------|--------|
| 8/3  | 12:00 | 曝光 | 普娃逆袭 | 拉新 | 待产 | 发片同事 | — | …脚本… | oc_xxx |
| 8/4  | 18:00 | 信任 | 老席自述 | 建信任 | 审核中 | 发片同事 | — | | |
| 8/5  | 12:00 | 留资 | 预算对比 | 转化 | 已发 | 发片同事 | 播放2.1w 留资23 | | |
| 8/6  | 12:00 | 曝光 | 政策解读 | 拉新 | 已排 | 发片同事 | — | | |
```

**字段说明**：
- **脚本内容**：定稿脚本压成单行入列，同步多维表格（老板群内「单开一列放脚本内容」可加）。
- **来源群**：排期创建时记录的所在群（本地记录，**不同步**多维表格），供发布前 1 小时提醒定位发到哪个群。

**规则**：
1. 三类内容按模板排期（默认节奏如每周3曝光+2信任+2留资），老板可改。排期具体到日期+发布时间（默认 12:00）。
2. 数据驱动微调：复盘agent写回数据，主控据此调整后续排期。
3. 老板可覆盖：老板说「下周三要3条曝光」，主控直接改表；排上某选题（「排上第1个」「定了这个」）→ 主控从席小题产出定位选题写入排期表。
4. **已发必须人工确认**：智能体不能发片、不自动标已发。流程：待产→审核中→待发→发片同事回「已发布」→智能体标「已发」→进入数据回流等待。
5. 多维表格为只读镜像（供老板看板），写路径始终走本地表 → 同步；不反向编辑 Base。
6. **只读镜像豁免（2026-08-05）**：**改表结构**（加列）属表结构变更，经 `lark-cli base +field-create` 直接改多维表格（群内「单开一列/加个字段」由老板/产品对话触发，见 §7.1）；**数据写入**仍走「本地 → 同步」，不反向编辑 Base。白名单外的新列会创建但不会自动填，需手动维护。
7. **定稿 → 问排期 → 记录**：写脚本审核通过后，小席当场问「要不要上排期表？排哪天几点？负责人是哪个发片同事？」，老板回「排 8/10 12:00」→ 记录该行（带脚本内容 + 负责人 + 来源群）；回「先不排」→ 不记；超时静默撤掉等待态，随时可再排。
8. **发布前 1 小时提醒**：小席循环每 30s 检查一次排期表，命中「今天 + 距发布时间 ≤60 分钟 + 状态∈(待产,待发) + 有来源群」的行 → 往来源群发提醒并 @ 负责人（owner=发片同事 → 用 `config/roles.json` 的 `publisher_open_ids[0]`），文案「⏰ 距发布还有 1 小时：8/10 12:00《选题》待发布，核对是否准备好」。同一条进程内只提醒一次。
9. **改排期禁止静默编造**：意图「改排期」但 params 为空、内容里又没有明确排期信息（日期/时间/数量/类型）时，**不生成占位行**，改为问老板「你要排哪条选题、排哪天几点？」。合法排期节奏（如「下周三要 3 条曝光」）params 必带 count/date，照常生成。

## 10. 自我迭代 / 双飞轮（席小习 修改飞轮 + 席小盘 数据飞轮）

### 10.1 修改飞轮（席小习）

```
老板在群里贴修改稿 / 说"这段改这样" / 纠正席小核审核看法
   │ 主控小席规划器判定 →「反馈修改」/「改审核看法」
   ▼
主控 ① 路由给产出专家重写  ② @席小习 对比 AI原版 vs 老板版（diff）
   → 分析每处改动原因 → 提炼成可复用规则（带 type：表达偏好/事实规则/内容策略/禁止事项）
   → 反馈修改：当场问老板「我学到这条规则了对吗」→ 确认后写入 memory/学习规则.md
   → 改审核看法：老板已直接拍板，跳过待确认直接落已确认规则
   ▼
席小题/席小文/席小核 的 prompt 都读 render_rules()（已确认规则，v1.5 按类型分组注入）
   → 下次生产自动遵循 → 产出更接近老板
```

**迭代机制 = 共享规则文件 + 三生产专家 prompt 都读**：老板改稿 → 席小习学差异 → 规则待确认 → 确认后写入 → 三个生产专家下次产出自动遵循，无需改代码。

**规则类型化（v1.5，防「一条例子被学成绝对真理」）**：每条规则带 `type` 字段，`render_rules` 按 禁止事项 → 事实规则 → 内容策略 → 表达偏好 分组注入——越靠前越硬守（禁止/事实要核对），越靠后越是方向不是绝对真理（内容/表达偏好当参考）。老板答复审核疑问拍板落规则标 `事实规则`；席小习提炼时按提示选 type，拿不准标内容策略。

### 10.2 数据飞轮（席小盘）

```
老板报实际数据：8/3 普娃逆袭 播放2.1w 留资23
   │ 主控识别「数据回流」
   ▼
主控存档排期表（回流完成）→ @席小盘
   → memory/数据回流.md 存档 + 数据分析（验证/推翻规律）
   → 排期调整建议（多做/少做/换角度）
   → memory/验证结论.md 沉淀
   ▼
主控 @席小题/@席小文 喂效果反馈（哪个选题/哪条内容效果如何）
   → 席小题/席小文 prompt 读 load_conclusions()（验证结论）
   → 选题/内容迭代
```

**迭代机制 = 共享验证结论文件 + 席小题/席小文 prompt 都读**：报数据 → 席小盘分析 → 验证结论 → 回喂生产专家 → 下次产出按效果数据迭代。

**分级学习**：
- L1 主观层：老板当场确认的偏好 → 直接写入风格档案，老板说了算。
- L2 客观层：数据回流验证的偏好 → 只有数据证明有效才强化。
- **按风格用户分库（Part B）**：学习规则落该聊天最近所用风格的用户库（默认老席 memory/学习规则.md，其余 memory/学习规则-<用户>.md），席小文写作只读对应风格库的已确认规则；反馈/学规则按该聊天最近风格路由到对应库，不污染他人。

**汇报机制**：每次改动当场求确认 + 定期（拟每周）发群汇总「本周学到的规则」，老板可删。
**本质**：规则库/记忆的积累（可解释、可撤销），非权重更新，不会顿悟只会积累。

## 11. 权限模型

通过 `im.message.receive_v1` 的 `sender` 识别发送者，映射角色（`config/roles.json`：`boss_open_ids`/`product_open_ids`/`publisher_open_ids`/`user_open_ids`）。

| 身份 | 权限 |
|---|---|
| **老板**（拉群后指定） | 全部权限：派单、改排期、**改表格结构（加列）**、确认规则、删规则、开圆桌、看排期表、反馈修改、追问 |
| **产品**（`product_open_ids`） | **与老板同级**，全部权限 |
| **发片同事**（`publisher_open_ids`） | 只允许：回「已发布」、回填数据（播放/留资），不能派单/改排期 |
| **用户**（`user_open_ids`） | 只读/反馈/追问：看排期表、看完整讨论、查记录、反馈修改、追问；写脚本/改排期/加列/派单等一律拦截「无权限：只有老板或产品能做这个，用户只读」 |

越权操作：皮肤层拦截，提示「无权限，需老板确认」。

**动作级权限（v1.5）**：拦截按「动作名」而非旧意图判定——`_PERMISSION_ADMIN`（出选题/写脚本/审核脚本/改排期/改表格结构/记素材/圆桌讨论/学规则/确认规则/数据回流/更新市场情报/**改审核看法**，仅老板/产品）；`_PERMISSION_USER_READONLY`（看排期表/看完整讨论/查记录/查已用选题/反馈修改/追问/要审核理由，用户可读）；`_THIRD_BUCKET`（确认已发布=发片同事可、确认排期/专家闲聊=任何人）。「未知」身份一律「无权限：当前身份未识别」。

**身份登记**：老板入群后告知谁老板级/谁用户级，登记进 `config/roles.json`（gitignore，不入库）。

## 12. 数据流

```
① 老板/同事在飞书群发消息
② 各 bot 皮肤层（lark-cli event监听，每 bot 独立 profile）收到 → 识别发送者身份
③ 小席收到 → 读会话记忆（7轮）→ 小席规划器（一次 LLM 调用产出自然回复 + 末尾可选【行动】JSON）→ 有动作则执行，无动作则用自然回复聊天
④ 主控 @对应专家（<at user_id> + 任务 + 【上下文】段）→ 专家 bot 自触发产出 → 主控 handle_bot_output 推进流水线/汇总
⑤ 本轮对话写入会话记忆（LRU 保留最近7轮，含专家 bot 输出）
⑥ 泛类内容入库：老板贴内容 +「记素材」→ 存 workspace/素材/；「看完整讨论」→ 拉群历史展示
⑦ 出选题：主控 @席小题（带本条消息原文+群历史上下文）→ 席小题读知识库 + 素材库 + 验证结论出题
⑧ 写脚本流水线：主控 @席小文 → 出稿 → **主控主动 @席小核 审核**（脚本走上下文，不刷屏）→ 席小核只发公开结论 + 疑问 + 「需要给您展示理由吗？」，详情存后台；三态判定：通过→收尾，不通过→@席小文 自动改正→复审（≤2 轮）仍不过请老板定夺，需老板确认→暂停等老板（wait_boss）；老板三选一：给确定答案→落已确认规则 + @席小文 按答案改→复审；回「可以了/继续/确定了」＝放行→当前脚本按通过定稿（不落规则）；回「不用了/算了」＝取消→保持原样；老板回短「要/看下」（且席小核刚邀约过「需要给您展示理由吗？」）或追问理由→直发存档的审核详情（v1.5 双层门：仅当邀约锚点在且短回应含理由词才直发，长消息不误触发）；要改→反馈修改重写 + 席小习diff学习
⑨ 人工发片 → 发片同事回「已发布」→ 排期表标「已发」
⑩ 数据回流（数据飞轮）：老板报数据 → 主控存档 → @席小盘 分析+排期建议 → **主控 @席小题/@席小文 喂效果反馈**
⑪ 圆桌讨论：老板喊「开圆桌/大家讨论下X」→ 主控抽议题 → 发【圆桌进行中】提示 → @席小题/席小文/席小核 三视角 → 到齐发【圆桌纪要】；超时补发缺失视角标注
```

## 13. 错误处理

| 异常 | 处理 |
|---|---|
| 小席规划器输出无法解析/无动作 | 模型判断纯闲聊 → 用规划器自然回复；只有规划器崩溃（异常）才落 `by_keyword` 关键词兜底（高信号指令不静默） |
| 非法/未知动作名（模型幻觉出白名单外的动作） | 按无动作处理，不进聊天兜底乱发（`parse_plan` 校验白名单） |
| 反馈修改/追问无上一条产出 | 回「没有找到可修改/可追问的上一条产出」，引导先出选题或写脚本 |
| 拉取群历史失败/未接入 | 出选题照常（只用素材库+会话）；「看完整讨论」回「拉取未接入或暂无」 |
| 圆桌无议题 | 回「圆桌需要一个议题，例如：大家讨论下第二条选题」，不空转 |
| 圆桌单专家调用失败 | 该专家标「未给出意见」，其余专家照常汇总 |
| 专家调用超时/失败 | 主控重试1次，仍失败则回群明说，不假装成功 |
| 知识库查不到事实 | 席小核不硬编，发群 @老板 提问，等确认 |
| 外部搜索也拿不准 | 同上去问老板，标「低置信度」，绝不编造 |
| 审核未过（红线/黄线） | 席小核只发公开结论+问理由，失败稿不进群；详情存后台；主控三态判定——明确拒稿信号才 @席小文 改正（≤2 轮），「通过：无红线」绝不误判为需改；需老板确认则暂停等老板，老板可给答案/回「可以了继续」放行定稿/回「不用了」取消 |
| 改排期 params 为空且无明确排期信息 | 不生成占位行，回「你要排哪条选题、排哪天几点？」，问清再排（禁止静默编造） |
| 定稿后问排期超时（wait_schedule） | 安静撤掉等待态，发「上排期的事先放着，要排随时说一声」，脚本已交付不受影响 |
| 加列失败/白名单外 | 加列失败明说「加列「XX」失败：原因」；白名单外列创建后提示「只有脚本内容列会自动填」 |
| LLM 输出为空/被思考吃满预算 | llm.py 逐步加大 max_tokens 重试 3 次；聊天预算 10000，接话不再退模板 |
| 数据回流缺失 | 排期表该条标「待回流」，复盘agent定期催老板补 |
| token接近熔断阈值 | 主控提前报告，建议暂停/降配 |
| 圆桌失控（刷屏/跑偏） | 主控中断，停止后续视角输出，已出的观点保留 |
| 权限越权 | 皮肤层拦截，提示「无权限，需老板确认」 |

**兜底原则：所有异常都走「问老板」或「明说失败」，绝不静默、绝不编造。**
