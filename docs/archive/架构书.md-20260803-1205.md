# 老席留学IP数字专家 · 架构书

> 版本：v1.0 · 2026-08-01
> 状态：设计已确认，待实现
> 配套文档：`需求与决策记录.md`（实时决策）、`PRD.md`（产品需求）、`RFC.md`（技术方案）

---

## 1. 项目定位

群聊里多个专家协助老板（老席）的内容生产，达到**大曝光、留资、获得信任**三个目标。
通过飞书群接入，多智能体协作，主控调度agent统一编排。

## 2. 目标现状

曝光、留资、信任**三个都没有**，全部要建，三引擎并行。不是选一个。

## 3. 边界（从0定义）

- **架构从0重建**：不沿用旧skill/旧agent。
- **业务资产保留当原料**：老席人设、家长原话、爆款规律、合规红线、费用数据等市场验证过的内容继续使用。
- 老资料（laoxi skill、老席审核agent、knowledge结构）只参考，不作为架构蓝本。

## 4. 系统架构

```
                    ┌─────────────────────────────┐
                    │     飞书群（老板唯一入口）       │
                    │  发需求 │ 看排期表 │ 喊讨论 │ 查疑问 │
                    └──────────────┬──────────────┘
                                   ▼
               ╔══════════════════╧══════════════════╗
               ║        【皮肤层】飞书bot（lark-cli）    ║
               ║   收发消息 │ 识别发送者身份 │ 权限拦截    ║
               ╚══════════════════╤══════════════════╝
                                   ▼ 管道（约定接口，消息与身份）
               ╔══════════════════╧══════════════════╗
               ║        【大脑层】主控调度agent         ║
               ║   收消息→判断触发形态→派单→汇总→发回   ║
               ║   管排期表 │ 熔断 │ token记账 │ 知识检索 ║
               ║   会话记忆(7轮) │ LLM意图识别(带上下文) ║
               ║   素材库 │ 完整讨论(拉群历史)            ║
               ╚═══════╤══════════════╤═══════════════╝
                       │派单          │写排期
                       ▼              ▼
        ┌──────────────┴──────────────┴──────────────┐
        │ 席小题 │ 席小文 │ 席小核 │ 席小习 │ 复盘agent │
        └────────────────────────────────────────────┘
                       │读写
                       ▼
        ┌────────────────────────────────────────────┐
        │   知识库 knowledge/ + workspace/ + memory/   │
        └────────────────────────────────────────────┘
```

### 4.1 分层原则（解耦）

- **皮肤层**（飞书bot）：只负责收发消息、识别发送者身份、权限拦截。
- **大脑层**（专家逻辑）：选题/写作/审核/学习/复盘，完全不依赖是哪个bot。
- **会话记忆**：大脑层按 `chat_id` 保存最近 7 轮对话（LRU），意图识别与专家派单都读它，实现「第1个」「这个脚本」等跨轮指代。
- **素材库**：用户投喂的泛类内容存 `workspace/素材/`（工作层），记素材入库，席小题出选题时读入。
- **完整讨论**：皮肤层经 lark-cli `+chat-messages-list` 拉取群历史，注入大脑层接缝 `_pull_history`，出选题/「看完整讨论」时使用。
- **圆桌讨论**：主控多视角并行逐步输出——先发【圆桌进行中】提示，再把议题派给席小题/席小文/席小核各出一版观点逐条实时发群，最后主控发【圆桌纪要】收尾。
- 两层通过**约定管道**传话（消息内容 + 身份信息）。
- **迁移影响**：单bot→多bot只换皮肤层（1个event监听→6个、文本标签→独立账号、1个app→6个app）。大脑层、知识库、排期表、权限、熔断全部复用。

## 5. 智能体组

| 角色 | 职责 | 备注 |
|---|---|---|
| **主控调度agent** | 收消息→判断触发→派单→汇总→发回；LLM意图识别（带7轮上下文）+会话记忆；管排期表/熔断/token记账/知识检索 | 顶层，升级自原「管家」 |
| **席小题** | 选题 + 调研合体 | 不单设席小材 |
| **席小文** | 写手，内嵌风格 | 含席小风 |
| **席小核** | 审核 + 核实 + 外部搜索核对 | 含席小实；已实现 v1：红线本地拦截 → LLM 全量审核 → Wikipedia 免key外核 → 核不到标「需老板确认 · 低置信度」 |
| **席小习** | 反馈学习：diff→规则提炼→确认→写入 | 新增，自我迭代核心；已实现 v1：学规则/确认规则 → memory/学习规则.md，已确认规则注入席小文 prompt |
| **复盘agent** | 数据回流→排期调整→知识库更新 | 新增，飞轮闭环；已实现 v1：报数据 → 排期表 data 落盘 + memory/数据回流.md → 验证结论 + 排期调整建议 |

**核实边界**：
- 库内核对：对照知识库查一致/出处 → AI能自动做
- 外部独立验证：从零验证外部事实 → AI不能独立保证，靠搜索+数据源权威性，责任在知识库维护

## 7. 角色触发规则

### 7.1 主控调度路由表

| 老板在群里说 | 主控做什么 |
|---|---|
| 「帮我出个选题」 | 派单给席小题 |
| 「写条脚本，关于XX」 | 走流水线：席小题→席小文→席小核 |
| 「看下排期表」 | 贴出当前排期表 |
| 「下周三前要3条曝光内容」 | 改排期表，标记任务 |
| 「大家讨论下XX」/「开圆桌会议」 | 触发圆桌模式：主控先发【圆桌进行中】提示，逐条实时发出席小题/席小文/席小核三视角观点，最后【圆桌纪要】收尾 |
| 「这个脚本不行」 | 反馈修改：从会话记忆找最近一条专家产出，路由给产出者改写 |
| 「为什么选这个角度」 | 追问：从会话记忆找最近一条专家产出，路由给产出者讲依据 |
| 「第1个写条脚本」 | 上下文关联：读会话记忆上轮选题，派席小文写第1条 |
| 「记素材：<内容>」 | 存进素材库 workspace/素材/ |
| 「看完整讨论」 | 皮肤层拉最近群历史并展示 |
| 「席小题，换选题方向」 | 名字关键词定向，只派席小题 |

### 7.2 触发形态（同时存在，不互斥）

1. 显式命令：@agent名 + 需求 → 直接派单
2. 隐式意图：说"写脚本/出选题/审核"（不@）→ LLM 识别意图
3. 上下文关联：说「第1个」「这个脚本」「为什么选这个」→ 带 7 轮会话记忆消解指代后路由
4. 默认状态：没触发关键词 → 主控回「需要我做什么？出选题/写脚本/看排期/讨论？」
5. 定向指挥：说专家名字 → 主控只派给该专家（等效软@）
6. 素材投喂：贴泛类内容 +「记素材」→ 入素材库；出选题时自动读素材库 + 最近群讨论
7. 圆桌讨论：说「开圆桌会议/大家讨论下X」→ 圆桌意图 → 主控逐步输出三视角

### 7.3 发言权边界

- 席小题/席小文/席小核/席小习/复盘agent：被派单才说话，平时不抢话（除圆桌模式）
- 主控调度：随时在场，兜底接话
- 老板：最高权限，可打断、可改、可删

## 8. 圆桌模式

- 触发：难选题，或老板喊「开圆桌会议」「大家讨论下X」。
- 实现（v2 已落地）：主控先发【圆桌进行中】提示（含议题），随后席小题（选题视角）/席小文（内容视角）/席小核（审核视角）各出一版 ≤180 字观点，**逐条实时发群**（经 `_emit` 即时发送接缝，不等全部生成完），最后主控发【圆桌纪要】收尾。一个大脑多视角并行、边出边发，讨论过程可见。
- 议题来源（`_roundtable_subject`）：① LLM 抽取的 topic 参数 → ② 内容里「第X条/第X个」定位上一条专家产出中的对应条目（支持中文数字「第二条」）→ ③ 上一条专家产出首行 → ④ 原文清洗后。无议题则回引导，不空转。
- 失控保护：单专家失败标记「未给出意见」不拖垮全场；每段观点 ≤180 字截断防刷屏。
- 发言权：圆桌属被派单形态，专家平时仍不抢话。

## 9. 排期表

主控调度唯一写权限。本机用本地Markdown表，稳定后迁飞书多维表格。

```
| 日期 | 内容类型 | 选题 | 目标 | 状态 | 负责人 | 数据回流 |
|------|---------|------|------|------|--------|---------|
| 8/3  | 曝光    | 普娃逆袭  | 拉新 | 待产 | 席小文 | — |
| 8/4  | 信任    | 老席自述  | 建信任 | 审核中 | 席小核 | — |
| 8/5  | 留资    | 预算对比  | 转化 | 已发 | 席小文 | 播放2.1w 留资23 |
| 8/6  | 曝光    | 政策解读  | 拉新 | 已排 | 席小文 | — |
```

**规则**：
1. 三类内容按模板排期（默认节奏如每周3曝光+2信任+2留资），老板可改。
2. 数据驱动微调：复盘agent写回数据，主控据此调整后续排期。
3. 老板可覆盖：老板说「下周三要3条曝光」，主控直接改表。
4. **已发必须人工确认**：智能体不能发片、不自动标已发。流程：待产→审核中→待发→发片同事回「已发布」→智能体标「已发」→进入数据回流等待。

## 10. 自我迭代 / 数据飞轮（席小习）

```
老板在群里贴修改稿 / 说"这段改这样"
   │
   ▼
席小习：对比 AI原版 vs 老板版（diff）
   → 分析每处改动原因
   → 提炼成可复用规则
   → 当场在群里问老板「我学到这条规则了对吗」
   → 老板确认后写入风格档案/memory
   ▼
下次生产 → 引用新规则 → 产出更接近老板
   ▼
发布 → 数据回流 → 用数据验证规则是否有效
```

**分级学习**：
- L1 主观层：老板当场确认的偏好 → 直接写入风格档案，老板说了算。
- L2 客观层：数据回流验证的偏好 → 只有数据证明有效才强化。

**汇报机制**：每次改动当场求确认（A）+ 定期（拟每周）发群汇总「本周学到的规则」，老板可删。
**本质**：规则库/记忆的积累（可解释、可撤销），非权重更新，不会顿悟只会积累。

## 11. 权限模型

通过 `im.message.receive_v1` 的 `sender` 识别发送者，映射角色。

| 身份 | 权限 |
|---|---|
| **老板**（拉群后指定） | 最高：派单、改排期、确认规则、删规则、开圆桌 |
| **发片同事** | 只允许：回「已发布」、回填数据（播放/留资），不能派单/改排期 |

越权操作：皮肤层拦截，提示「无权限，需老板确认」。

## 12. 数据流

```
① 老板/同事在飞书群发消息
② 皮肤层（lark-cli event监听）收到 → 识别发送者身份
③ 管道传给大脑层 → 主控调度读会话记忆（7轮）→ LLM意图识别（带上下文）→ 判断触发形态
④ 派单给对应专家（带上下文）→ 专家产出 → 主控汇总 → 皮肤发回群
⑤ 本轮对话写入会话记忆（LRU 保留最近7轮）
⑥ 泛类内容入库：老板贴内容 +「记素材」→ 皮肤层存 workspace/素材/；「看完整讨论」→ 皮肤层拉群历史展示
⑦ 出选题：席小题读知识库 + 素材库（recent_materials）+ 最近群讨论（皮肤层拉取）出题
⑧ 老板确认/修改 → 满意→存workspace/产出；不满意→反馈修改重写 或 席小习diff学习
⑨ 人工发片 → 发片同事回「已发布」→ 排期表标「已发」
⑩ 复盘agent分析数据 → 沉淀验证结论到memory → 通知主控调后续排期
⑪ 圆桌讨论：老板喊「开圆桌/大家讨论下X」→ 主控抽议题（第X条/原文）→ 发【圆桌进行中】提示 → 派席小题/席小文/席小核三视角各一版**逐条实时发群** → 最后【圆桌纪要】收尾
```

## 13. 错误处理

| 异常 | 处理 |
|---|---|
| 触发识别不出意图 | 主控回「我没听懂，你要出选题/写脚本/看排期/讨论？」 |
| 反馈修改/追问无上一条产出 | 回「没有找到可修改/可追问的上一条产出」，引导先出选题或写脚本 |
| 拉取群历史失败/未接入 | 出选题照常（只用素材库+会话）；「看完整讨论」回「拉取未接入或暂无」 |
| 圆桌无议题 | 回「圆桌需要一个议题，例如：大家讨论下第二条选题」，不空转 |
| 圆桌单专家调用失败 | 该专家标「未给出意见」，其余专家照常汇总 |
| 专家调用超时/失败 | 主控重试1次，仍失败则回群明说，不假装成功 |
| 知识库查不到事实 | 席小核不硬编，发群 @老板 提问，等确认 |
| 外部搜索也拿不准 | 同上去问老板，标「低置信度」，绝不编造 |
| 审核未过（红线） | 退回席小文重写，注明被拒原因，不把失败稿发群 |
| 数据回流缺失 | 排期表该条标「待回流」，复盘agent定期催老板补 |
| token接近熔断阈值 | 主控提前报告，建议暂停/降配 |
| 圆桌失控（刷屏/跑偏） | 主控中断，停止后续视角输出，已出的观点保留 |
| 权限越权 | 皮肤层拦截，提示「无权限，需老板确认」 |

**兜底原则：所有异常都走「问老板」或「明说失败」，绝不静默、绝不编造。**

## 14. 熔断机制

- 记录每次调用的token消耗。
- 累计到阈值（先设 **1亿token**，按费用可调）触发熔断，主动报告，不闷头烧钱。

## 15. 部署路径

- **阶段1（本机）**：单bot，成本0，验证架构。lark-cli已装已登录。
- **阶段2（迁多bot）**：确认有价值后，只换皮肤层。需建飞书自建应用（6个bot或1个bot）凭证。
- **阶段3（可选独立服务）**：云服务器 + 常驻进程，7×24可用。需额外投资。
