# 处理规范：直播稿四类提取规则

处理直播逐字稿时按以下 4 类提取，每类产出一份 `knowledge/` 沉淀。借鉴土豆「结构化数据清洗工具」的五字段原则，按直播稿特点定制。

## 输入

- 直播逐字稿（docx/txt，带说话人+时间戳）
- 成稿脚本（已粗清洗的直播稿件，如 `老席直播稿件.docx`）

## 清洗总则

- **去噪**：电流声、设备调试、团队杂话、无意义重复
- **去重**：同一话术直播循环 N 遍 → 只留最优版本 + 记录变体
- **口语还原**：指代不清的补全成完整句子（如「那这个呢」→ 完整问句）
- **追溯**：每类每条带来源稿件、日期、时间点

---

## 一、语言风格 → `knowledge/人设/老席直播语言风格.md`

字段：**特征 + 直播原话例句 + 使用场景**

分类：
- 口头禅
- 指令式互动 CTA（打一波X / 拍完回打谢谢习校长）
- 身份背书句式
- 反复重讲循环结构
- 数字对比 / 排比
- 反常识钩子
- 人设自嘲话术（端屎端尿 / 精英女流氓 / 黑头发黑眼镜）

与「老席创作要求会纪要」互为印证：纪要是**要求**，本文档是**实战印证**。

## 二、内容口径 → `knowledge/业务事实/直播口径.md`

字段：**事实点 + 直播讲法 + 与现有档案差异备注**

覆盖主题：项目定义/学制/年龄线/费用/入学门槛/毕业保障/学历认证/就业薪资/院校对标/市场数据

去重：先查 `knowledge/业务事实/`（项目详情/费用数据/院校信息/就业数据），重复标「已覆盖」，差异才记。不设直播专用框，按对内容创作的价值组织。

## 三、直播语料 → `knowledge/直播语料/<日期-主题>直播语料.md`

字段：**原话 + 功能标签 + 来源时间点**

功能分类：开场互动 / 拉预期 / 讲项目 / 讲费用 / 处理反对意见 / 催单CTA / 收尾

同一话术多版：保留最优版，变体归入该条备注。

## 四、家长问题（带应答） → `knowledge/家长画像/直播问题库.md`

字段：**问题 + 席老师应答 + 类型标签 + 来源时间点**

来源：直播公屏提问，与「家长原话库」（闭门会真实连麦）区分。

规则：问题去重、口语还原成完整问句；应答以席老师现场回答为准，答得含糊标「（待补充）」。

类型标签：门槛 / 毕业 / 费用 / 认证 / 生活 / 路径 / 就业 / 其他。

## 输出与追溯

- 4 类沉淀写入 `knowledge/` 对应目录（见 `清洗工作流/CLAUDE.md` 沉淀去向表）
- 每份稿处理完，补写 `产出/处理记录-YYYY-MM-DD.md`：处理清单 / 去重结论 / 4 类统计
